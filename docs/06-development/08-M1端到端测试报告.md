## 3. 发现的缺陷与修复
| # | 现象 | 根因 | 修复（提交） |
|---|---|---|---|
| B1 | E15（大量 DEL `0x7F` 等控制字符）入库 done，切块正文含不可见控制字符 | `clean_text` 只去掉 `ord < 32` 的 C0 字符，DEL 与 C1（0x80–0x9F）漏网；解码时 `errors="replace"` 产生的 U+FFFD 也不检查 | `clean_text` 去除全部 C0/C1 控制字符；TXT 解码后 U+FFFD 占非空白字符 > 5% 判为乱码并报“文本疑似乱码”（`07b589d`） |
| B2 | 07 运费表第 2 块以“公斤计费；时效自出库起计算。”开头（半句） | 下一段几乎占满块时缩减重叠，用按 token 截断的 `_suffix_within`，违背“重叠以完整句子开头” | 缩减时只保留末尾完整句子，放不下则该块不重叠（`efb5d69`） |

排查后确认**不是缺陷**：psql `left()` 输出中的“续重��公斤”是终端按字节截断显示造成的，库内文本无 U+FFFD。

## 4. 检索质量评测
方法（按 RAG 设计文档参数）：向量 top 20（Qdrant，再按 PG 可检索规则过滤）、全文 top 20（`build_tsquery` OR 查询 + `ts_rank_cd`）、RRF k=60 取 top 30、`qwen3.7-text-rerank` 对 `heading_path + 正文` 重排（父子模式按父块去重、重排父块正文）。问题集 61 题：51 题可回答（口语 / 同义 / 精确条款 / 数字 / 表格 / 版本与型号混淆 / 英文）、10+1 题不可回答。判定：排名位置上的块来自期望文档且包含任一证据片段。

不可回答题的重排最高分（main）：0.128、0.284、0.293、0.349、0.369、0.395、0.411、0.423、0.438、0.485、**0.671**（“可以用星河豆购买彩票吗？”——星河豆用途段落高度相关但不含答案）。可回答且 Top1 正确的题，重排 Top1 分数最小 0.824、P10 0.926、中位数 0.980。向量最高分在不可回答题上为 0.37–0.68，与可回答题大量重叠，**不能用向量分做拒答阈值**。

失败与观察：
- 第一版问题集有 4 题未命中，复核后均为**标注问题**而非检索问题：q01、q47 的 Top1 是 FAQ 中同样正确的答案（补充期望文档）；原 q51“偏远地区上门取件”、q52“账号被盗”语料中并无答案（改写 q51，q52 移入不可回答）。修订后重新计算如上表。
- 全文单路明显偏弱（Hit@1 ≈ 0.62）：OR tsquery 中“几天 / 多久 / 一次 / 是多少”等疑问词与泛化词贡献大量噪声命中；jieba 把“无理由”“加重排序”切成“理由”“加重”等。全文主要价值在精确编号（XH-00405、E07、第三十五条、合同号）。
- RRF 等权融合在本集上 Hit@1 低于纯向量（0.80 vs 0.88），弱的一路把噪声带进前排；重排后差异消失，说明召回（Hit@5 0.92–0.96）足够、排序靠重排。
- 上下文前缀在本语料上无可测收益（±1 题，在噪声内）；父子模式召回 Hit@3/5 略好（0.941/0.961），重排后与 flat 相同，但送入 LLM 的上下文更长（1024 token 父块）。
- 评测局限：题量 51、证据片段判定较宽（个别题证据在多块出现）、语料为生成文本、重排后 100% 说明本集对重排偏易，不代表线上效果。

## 5. 结论与 M2 建议
1. **默认参数保持** `vector_top_k=20`、`keyword_top_k=20`、RRF k=60、`fuse_top_k=30`、`rerank_top_n=5`；重排是必要环节（M2.2 rerank 失败回退 RRF 顺序时，质量会降到上表“混合 RRF”水平）。
2. **拒答阈值**：设计值 `rerank_threshold=0.35` 偏低（11 道不可回答题有 8 道高于 0.35）。建议 M2 默认 `rerank_threshold=0.5`、`judge_gray_upper=0.8`：可回答题 Top1 全部 ≥ 0.824 直接通过；0.5–0.8 灰区交给 judge（本集唯一高分不可回答题 0.671 落入灰区）。服务器上用真实知识库样本复核后再定。
3. **全文检索**：M2.2 关键词查询前去除疑问词 / 停用词（如“多少、几天、怎么、是否、吗”），并考虑 M2.2b 的加权融合（如向量 0.7 / 全文 0.3）作为可选项。
4. **上下文前缀**：本集无收益但也无损失，保持默认开启（对“同名小节在不同文档”更稳），在真实语料上再评估。
5. **按文档覆盖切块预设**：现在 `chunk_config` 按应用生效，一个应用内法规、FAQ、手册只能用同一预设（main 中法规按 general 切成 41 块、条文边界丢失）。建议 M4 知识库后台支持文档级预设覆盖。
6. **解析质量**：PDF 中每行为独立文本块时按行成段（本合成 PDF 如此），句子被换行打断影响分词；TXT 无标题结构；超大表每块重复表头（符合设计）。建议 M2 前补一个“PDF 同字号、行距小、上一行未以句末标点结束则续行”的合并规则并以真实 PDF 样本验证。

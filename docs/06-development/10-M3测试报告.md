## 2. M3.1 ① `last_used_at`：Redis 分钟分桶 + beat 批量落库

**落地要点**：鉴权成功（限流通过后）向 `{prefix}keyuse:{yyyymmddHHMM}`（UTC 分钟桶）`HSET key_id=unix_ts` 并 `EXPIRE 900`，**不写库**；beat 任务 `aics.flush_key_usage`（maintenance 队列，每 60 秒，`expires` 55 秒）读最近 11 个桶（当前分钟只读不删，历史桶读后 `DEL`），按键取最大时间戳，用**一条** `UPDATE api_keys SET last_used_at = greatest(last_used_at, to_timestamp(:ts))` 落库。分桶让“过去的桶不可变”，因此不需要 Lua，也没有 `HGETALL`/`HDEL` 之间的丢写竞态（后续计划 §M3.1 的推荐方案）。`to_timestamp` 是必需的：`greatest(timestamptz, integer)` 在 PG 上不存在；`GREATEST` 会忽略 NULL，所以首次使用也能写入。

Redis 异常只记 `apikeys.key_usage_unavailable` 警告并放行（与限流 fail-open 一致）；鉴权失败路径不写标记。

## 3. M3.1 ② IP 白名单与可信代理

**判定顺序**（`ApiKeyAuthenticator.authenticate`）：bearer → HMAC → 吊销 → 过期 → 应用绑定（跨应用 404）→ 应用禁用 → **IP 白名单** → scope → 限流 → 使用标记。白名单检查放在 scope 之前、限流之前，所以被拒请求**不消耗配额**、也不产生 `last_used_at`。

**语义**：客户端 IP 取 `request.client.host`；只有当该地址本身落在新配置 `AICS_TRUSTED_PROXIES`（逗号分隔 CIDR，默认空 = 不信任任何代理）内时，才从右往左取 `X-Forwarded-For` 中第一个非可信地址；链里出现无法解析的地址时返回 `None`（宁可不放行，也不猜）。白名单存在但客户端地址未知 → 同样 `403 IP_NOT_ALLOWED`（fail-closed）。直连（对端不可信）时请求头完全无效，伪造无效。

缓存的 Key 记录带上 `ip_allowlist`，所以命中 60 秒缓存也照样校验；`set_ip_allowlist`（M4.5 的管理接口会复用）改写后立即删除该 Key 的缓存，改严即刻生效。CIDR 校验在写入前完成（非法 → `422 VALIDATION_ERROR`，不交给 PostgreSQL 报 500），单个 IP 按 `/32`、`/128`，按掩码归一化（`10.1.2.3/8` → `10.0.0.0/8`）。

## 7. M3.2 ② 幂等键与写接口（`0d456ec`）

**幂等键**（`core/idempotency.py`，FastAPI 依赖形式，纯 Redis）：请求头 `Idempotency-Key`（≤128 字符）→ `SET {prefix}idem:{key_id}:{key} NX EX 86400` 写占位 `{"state":"processing","sha":…}`；处理中重复 → `409 CONFLICT`；同一键但请求体摘要不同 → `409 IDEMPOTENCY_CONFLICT`；成功后把占位覆写成 `{"state":"done","status":…,"body":…}`（响应体上限 64 KB）并直接回放；非 2xx 与异常一律**删占位**，允许客户端立即重试；Redis 不可用则**放行**并记 `idempotency.unavailable` 警告（上传本身还有 `content_hash` 去重兜底，与设计讨论 0009 D9 一致）。请求体摘要：multipart 取“文件 SHA-256 + 其它字段的规范 JSON”，JSON 请求取规范化后的整体。

**写接口**（`modules/knowledge/router.py`，scope `kb:write`）：上传 `POST /documents`（202）、URL 导入 `POST /documents/url`（202）、替换 `PUT /documents/{document_id}/file`（202；内容未变 200 `{"unchanged":true}`；与其它文档重复 409 `DUPLICATE_DOCUMENT`；构建中 409 `DOCUMENT_BUSY`）、重建 `POST /documents/{document_id}/reindex`（202）、改标题与元数据 `PATCH /documents/{document_id}`（立即生效）、删除 `DELETE /documents/{document_id}`（204，立即不可检索、异步清理）。上传**按 1 MB 分块流式累加**，超过 `AICS_UPLOAD_MAX_MB` 立刻 `413 FILE_TOO_LARGE`（不把整个文件读进内存，服务器内存紧张）；扩展名先快速拒绝 `400 UNSUPPORTED_FILE_TYPE`，魔数仍由 `ingest.parsers` 判定；`metadata` 上限 8 KB、`url` 上限 2048 字符。

**用完即关**：`_Prepared.stateless`（由「请求没带 conversation_id」推出），`_execute` 的 `finally` 调 `_close_stateless`，复用 `ConversationRepository.close`（条件单行更新，天然幂等）写 `close_reason=stateless`；同时 `_after_turn` 直接返回——不压缩、不写事实、不产生空闲提醒；`idle_sweep` 只扫 `status='active'`，所以关掉之后不会再被扫到。

**认证**：`/v1` 路径里没有 `{app_id}`，`require_scope` 依赖路径参数取应用，因此新增 `Authenticator.authenticate_key(...)` 与 `require_key_scope(...)`。`ApiKeyAuthenticator` 拆成 `_resolve`（bearer → 缓存/PG → HMAC → 吊销 → 过期 → 解析客户端 IP）与 `_admit`（应用状态 → IP 白名单 → scope → 限流 → 用量标记 → `Principal`）：`authenticate` = `_resolve` + 应用绑定/删除中 404 + `_admit`，`authenticate_key` = `_resolve` + 删除中 404 + `_admit`，判定顺序与原实现逐条一致（既有拒绝矩阵用例一行未改）。

## 11. M3.3 ② OpenAI 兼容路由（`5a1122e`）

**两个端点**：`GET /v1/models`（只返回 Key 所属应用）、`POST /v1/chat/completions`（阻塞 + 流式同一条执行路径）。纯函数与请求模型在 `modules/chat/openai.py`，路由在 `modules/chat/openai_router.py`。

| 契约点 | 实现 |
|---|---|
| `model` | 必须等于 Key 所属应用，否则 404 `model_not_found` |
| `messages` | 最后一条必须是 `user`（否则 422）；客户端 `system` 忽略；历史取最后一条 user 之前的 `user`/`assistant`，按应用预算裁剪（超预算且 `openai_temp_summary` 时用请求内临时摘要） |
| 不可用字段 | `tools` / `functions` / `n` 忽略（`n>1` 只回 1 个 choice） |
| `temperature` / `max_tokens` | 只能**收窄**：`min(请求, 应用配置)`；其它键忽略（`model_copy` 会绕过校验，先在 `clamp_overrides` 里过滤） |
| 无 `X-AICS-Conversation-Id` | 新建 `channel=openai` 会话、只写本轮、本轮结束即关（`close_reason=stateless`），响应回带 `aics.conversation_id` 但不作为下次历史 |
| 带该头 | 值必须是本应用会话 id，否则 404 `conversation_not_found`；会话已关闭 → 自动新建并回填 `aics.previous_conversation_id` |
| 应答形态 | `chat.completion`（`chatcmpl-…`、`usage`）+ `aics` 扩展（`message_id`/`conversation_id`/`previous_conversation_id`/`reply_by`/`handoff_status`/`answer_type`/`handoff`/`intent`/`citations`） |
| 流式 | 每个增量一个 `chat.completion.chunk`，末 chunk 带 `aics` 与 `usage`，随后 `data: [DONE]`；空闲沿用原生 SSE 的注释行心跳（15 s） |
| 错误体 | `{"error":{"message","type","code"}}`；`main.py` 的三个异常处理器按 `request.url.path.startswith("/v1/")` 分流，原生接口响应体一字未改（有回归用例） |

**本步发现的真实缺陷**：`JSONResponse` 直接序列化含 UUID 的 `aics` 字段会 500（Starlette 用 `json.dumps`）——改为与其它路由一致的 `jsonable_encoder`。这是单测抓到的，不是集成环境。

| 层 | 用例 | 断言 |
|---|---|---|
| 单元 `tests/unit/test_openai_api.py`（53 例） | 请求解析矩阵 | 最后一条非 user / 空 messages / 超长 / 非法 UUID / `content` 分片等拒绝分支 |
| | 应答、分片与错误体 | `chat.completion`、`chunk`、`aics` 字段、`[DONE]`、错误码映射 |
| | 路由 | 假认证器（`authenticate_key`）+ 假服务：model 不匹配 404、401/403/422 分支、限流头透传 |
| | `clamp_overrides` 矩阵 | 只收窄、非法值忽略、不污染应用配置 |

## 13. M3.3 预算与结论

- 真实模型费用 **0 元**（集成用例用假模型；计划里“真实模型 10 轮 × 2 次、约 0.3 元”的演示改为服务器侧待复验项）。

- **集成用例的落点**：M3.3 的 12 条集成用例（隔离 4 + 官方 SDK 8）已于 2026-10-17 在本机 Docker 栈上用真 PG + Redis 跑通（见 §14）；仍待服务器复验的是：无状态会话在真实 worker / beat 下不被空闲扫描误伤、临时摘要在真实模型下的 15 s 超时行为。

## 14. 本机集成复验（2026-10-17，本机 Docker 栈）

### 14.1 环境

本机 `docker/compose.yaml` 起 PostgreSQL 16.15、Redis 8.2（ACL 与服务器同配置：`~aics:* ~celery-task-meta-* ~chord-unlock-* &aics:* … +@all -@admin -@dangerous`）、RabbitMQ 4.3、Qdrant v1.18.2，**版本与服务器一致**，端口只绑 `127.0.0.1`。`docker\dev-stack.cmd test` 注入 `AICS_TEST_DB_URL` / `AICS_TEST_REDIS_URL` / `AICS_TEST_QDRANT_URL` / `AICS_TEST_QDRANT_API_KEY` 后跑 `pytest -m integration`（PG 用 `aics_test` 库、Redis 用 db 7，与开发数据隔离）。

### 14.2 过程与结果

| 阶段 | 结果 |
| | --- |
| 首次运行 | `1 failed / 2 passed / 186 errors`：每条集成用例的 `alembic upgrade head` 都失败，`UnicodeDecodeError: 'gbk' codec can't decode byte 0xae in position 24`——Alembic 以 `encoding="locale"` 读 `alembic.ini`，中文 Windows 下是 GBK，而该文件第 1 行是中文注释 |

### 14.3 复验发现并修复的缺陷

| 编号 | 现象 | 根因 | 修法 |

### 14.4 结论

- M3.1 / M3.2 / M3.3 的集成用例（含迁移 `0011` 往返、跨应用隔离、幂等回放与冲突、官方 SDK 直连）现在都在本机真依赖上跑通，**不再依赖服务器凭据**；待复验清单里「开发机无 PG / Redis / Qdrant（本机全部反选）」一类条目已可本机执行。
- ISSUE-49 是本次复验最大的收获：它由 M3.3 阶段② 引入，只影响原生 `/chat` 的**多轮记忆链路**（单轮问答完全正常），假运行时单测与本机跑不了的集成测试都照不到——「假运行时单测」与「真依赖集成」两层必须都在。
- 仍需服务器：生产 RabbitMQ 与实际容器网络、Nginx 代理链与 `AICS_TRUSTED_PROXIES`、真实模型与真实语料、压测与备份演练。

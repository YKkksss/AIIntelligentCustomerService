# 开发环境搭建（Windows 11）

## 1. 安装工具
```powershell
winget install --id=astral-sh.uv -e
winget install OpenJS.NodeJS.LTS
winget install Git.Git
uv python install 3.12
```
可选：`winget install DBeaver.DBeaver.Community`（看数据库）。

## 2. 获取代码
```powershell
cd G:\code\projects
git clone https://github.com/<org>/AIIntelligentCustomerService.git
cd AIIntelligentCustomerService
git switch dev            # 日常开发在 dev，不在 main
```

## 3. 配置
```powershell
Copy-Item .env.example .env   # 后端读取仓库根目录 .env；backend\.env（若存在）优先
notepad .env              # 填入密码与 Key（找负责人获取，不要通过聊天发送）
```
确认服务器服务已按《服务器准备》建好，并可连通：
```powershell
Test-NetConnection 192.168.110.86 -Port 5432
Test-NetConnection 192.168.110.86 -Port 6379
Test-NetConnection 192.168.110.86 -Port 5672
Test-NetConnection 192.168.110.86 -Port 6333
```

## 4. 后端
```powershell
cd backend
uv sync                                  # 创建 .venv 并安装依赖
uv run alembic upgrade head              # 建表
uv run aics-cli bootstrap-admin          # M4.1 起可用（读取 .env 中的初始管理员）；之前是占位命令
uv run aics-cli apikey create --app <app_id> --name dev --scopes chat   # 建开放接口 Key（明文只输出一次）
uv run aics-api                          # 等价于 uvicorn aics.main:create_app --factory（dev 下自动 reload）
```
另开终端启动 Worker（Windows 下 Celery 必须用 solo 或 threads 池）：
```powershell
cd backend
uv run celery -A aics.tasks.celery_app worker -Q ingest,context,eval,maintenance --pool=threads -c 4 -l info
uv run celery -A aics.tasks.celery_app beat -l info     # 需要定时任务时
```
> 开发期一个 worker 消费全部 4 个队列即可（`context` 必须包含在内，否则会话压缩不会执行）；生产环境 `context` 由独立 worker 进程消费，见[应用部署](../07-deployment/03-应用部署.md)。

打开 http://localhost:8000/docs 和 http://localhost:8000/readyz 。

## 5. 前端
```powershell
cd frontend
npm ci
npm run dev        # http://localhost:5173
```

## 6. 代码检查
```powershell
uv tool install pre-commit
pre-commit install
pre-commit run --all-files
```
后端单独检查（与 CI 相同）：
```powershell
cd backend
uv run ruff check . ; uv run ruff format --check .
uv run lint-imports                          # 模块依赖规则
uv run python -m aics.core.prompts check     # 提示词版本；改了提示词正文并 +1 version 后运行 update
uv run pytest --cov=aics
$env:AICS_TEST_DB_URL="postgresql+asyncpg://aics:<AICS_DB_PASSWORD>@192.168.110.86:5432/aics_test"; uv run pytest -m integration   # 迁移往返测试
```

## 7. 常见问题
| 现象 | 处理 |
|---|---|
| `/readyz` 中 qdrant 失败 | 检查 `AICS_QDRANT_API_KEY` 是否为 KnowledgeFlow Qdrant 的当前 Key（向负责人确认） |
| Redis 报 `NOPERM` | ACL 用户 `aics` 只允许 `aics:*` 等前缀与非管理命令（见服务器准备 §3）；检查 key 前缀与是否用了 `KEYS`/`INFO` 等命令 |
| Celery 在 Windows 卡住不执行 | 确认用了 `--pool=threads` 或 `--pool=solo` |
| 中文乱码 | PowerShell 执行 `chcp 65001`；文件统一 UTF-8 无 BOM |
| `count_tokens` 首次调用卡住或报网络错误 | tiktoken 首次需下载 cl100k_base 编码；无外网时设置 `TIKTOKEN_CACHE_DIR` 指向已缓存目录 |
| 百炼 401 | Key 是否已轮换后更新到 .env；地域是否为北京 |
| 分类经常 2 s 超时、`intent_source=fallback` | `AICS_MODELS` 中 `deepseek-flash` 是否带 `"thinking":"toggle"`（见 `.env.example`） |
| 尚无管理后台，怎么建应用 | M4.2 之前用脚本：参考 `backend/scripts/e2e_m2/e2e_m26_http.py` 与 `scripts/e2e_m1/run_e2e.py` 中用 `AppService`（`create_app` / `update_app`）建、改应用，用 `ApiKeyService.create` 或 `aics-cli apikey create` 建 Key 的做法 |

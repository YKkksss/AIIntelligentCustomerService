# 测试策略

| 层级 | 范围 | 工具 | 运行 |
|---|---|---|---|
| 单元 | 解析器、切块器、RRF、引用解析、阈值判断、Key 哈希、限流算法、配置校验（`AppRagConfig`、80% 窗口）、`rag.intent` 纯函数、`count_tokens`、`build_tsquery`、`load_context` 组装算法（用内存版 `ConversationStore`）、提示词 front-matter 版本检查、import-linter 依赖规则 | pytest | 每次提交（CI） |
| 集成 | 迁移往返（`upgrade → check → downgrade → upgrade`，`AICS_TEST_DB_URL`，`pytest -m integration`）；API + 真实 PG/Redis/Qdrant（测试库 `aics_test`（服务器为 PG 16.15，本机可用 16 或更高）、Redis 库 7、Qdrant 集合前缀 `aics_test_`）；模型用假实现 | pytest-asyncio、httpx.AsyncClient | CI（服务容器）/ 本地 |
| 契约 | 模型供应商 HTTP 请求格式 | respx 录制 mock | CI |
| 冒烟 | 真实 DeepSeek + 百炼跑 5 个问题 | `pytest -m live` | 发布前手动 |
| 评测 | 准确率指标 | `aics-cli eval` | 改动 rag/ingest/提示词时、发布前 |
| E2E | 后台关键路径：登录→建应用→上传→调试对话 | Playwright | 发布前 |

**必须覆盖的测试用例**
- 隔离：A 应用 Key 访问 B 应用文档/会话/对话 → 404；Qdrant 检索结果全部属于本应用。
- 拒答：知识库无关问题 → `refused`；转人工关键词 → `handoff`。
- 注入：文档中含"忽略以上指令"时回答不受影响（评测集中设专门用例）。
- 幂等：同一 `Idempotency-Key` 重复上传只产生一个文档；任务重复执行结果一致。
- SSE：事件顺序 start → trace?（仅调试）→ citations?（仅判定可答）→ delta* → end；拒答/转人工/非 kb_qa 无 citations；客户端断开后 assistant 消息标 `interrupted=true`。
- 落库顺序：生成前 user 消息已存在；上游出错时 assistant 消息 `answer_type=error`。
- 会话空闲：`idle_sweep` 在关闭前发提醒（system/idle_notice）、到时关闭；期间有新消息则不提醒不关闭；重复执行幂等；向已关闭会话发消息自动新建并返回 `previous_conversation_id`；`idle_close_minutes=1` 不提醒。
- 转人工：状态机各迁移与 `409 HANDOFF_STATE_CONFLICT`；continue / wait 两种模式下 pending 与 accepted 的回复（`reply_by`）；accepted 期间空闲不关闭；release 后 AI 恢复；排队超时（两种模式）→ released/queue_timeout、发话术、待回访、事件，期间被接入则不处理；服务时间边界（时区、多时段、区间右开、未配置 = 7×24）与非服务时间不进 pending；接入后无消息超时关闭会话；后台强制释放；`handoff_queue_timeout_minutes ≥ idle_close_minutes` 保存被拒；待回访列表与清除。
- Webhook：签名可被示例代码校验；非 2xx 按退避重试；私网地址被拒；debug/eval 渠道不发送。
- 版本化构建：替换/重建期间旧版本可检索，切换后旧切块不再命中；替换文件哈希规则三种情况。
- 删除：应用 `deleting` 后进行中的入库任务中止（job `cancelled`）。
- flagged 切块复核前检索不到。
- 删除：删除后立即检索不到。
- 统计：`aggregate_daily_stats` 重复执行结果一致，且不含 debug/eval 渠道。

**假模型**：`FakeLLM`（按规则回固定文本含 `[1]`）、`FakeEmbedder`（哈希生成确定性向量）、`FakeReranker`（按关键词重叠打分），保证测试离线、稳定、免费。

覆盖率：CI 运行 `pytest --cov=aics --cov-fail-under=80`，统计范围是**整个 `aics` 包的单元测试**（`addopts` 默认排除 `integration` 与 `live`，`cli.py` 不计入），低于 80% 失败。2026-10-17 为 80.58%，余量很小：新代码必须自带单元测试；只能靠集成测试覆盖的 SQL 也要写集成测试，但它们不计入门槛。前端（M4.1 起）用 Vitest 覆盖 `src/api`、`src/stores`、`src/utils`、`src/composables`，门槛同为 80%。

**标记与运行**：`-m integration` 需要 `AICS_TEST_DB_URL`（PG）与 `AICS_TEST_QDRANT_URL`（可为 `:memory:`），Redis 用本机或 `fake_redis`；`-m live` 调真实模型，发布前手动。真实模型的端到端与评测脚本放在 `backend/scripts/e2e_m*/`，结果 JSON 存 `results/` 并写进测试报告。

**测试数据**：测试文档与对话要接近真实长度（几千到几万字、20 轮以上），用虚构内容；记忆相关改动必须重跑长对话评测 `scripts/e2e_m2/eval_m25.py`。

## 解析快照
- `tests/fixtures/docs/` 下的样例文件（虚构内容）由 `make_fixtures.py` 生成并提交；`tests/unit/test_parsers_snapshot.py` 对每个样例的解析结果与 120/30 切块结果做 JSON 快照比对（`tests/fixtures/snapshots/`）。
- 解析或切块规则有意变更时：`AICS_UPDATE_SNAPSHOTS=1 uv run pytest tests/unit/test_parsers_snapshot.py` 更新快照，并在评审中检查 diff。

## 测试结果与默认值（常设规则）
每轮测试 / 评测结束后，结果写入 `docs/06-development/` 下的测试报告（M1–M2：`08-M1端到端测试报告.md`；M3 起每个里程碑一份：`10-M3测试报告.md`、`11-M4测试报告.md`、`12-M5测试报告.md`、`13-M6测试报告.md`），并把测试支持的最佳取值采纳为系统默认值，统一登记在[参数默认值与依据](09-参数默认值与依据.md)（含依据、日期与“待服务器复验”标注），再同步代码、设计文档与测试；测试未覆盖的参数不改。

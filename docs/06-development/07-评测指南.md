# 评测指南

评测回答一个问题：**改了配置 / 提示词 / 模型之后，客服是变好了还是变差了？**

## 1. 准备评测集
- 每个应用至少 50 题：约 70% 可答题（覆盖每份重要文档）、20% 不可答题（相关但资料没有，如"你们支持分期吗"）、10% 多轮追问与刁钻问题（含注入尝试）。
- CSV 格式：
```csv
question,expected_answer,expected_documents,should_refuse,tags,expected_intent
退货多久到账？,审核通过后3-5个工作日原路退回,0192f0c1-7a2b-7c3d-9e4f-123456789abc,false,退款,kb_qa
运费谁承担？,质量问题由商家承担,售后政策.pdf,false,运费,kb_qa
你们支持分期付款吗？,,,true,不可答,kb_qa
你好呀~,,,false,寒暄,chitchat
```
`expected_documents` 多个用 `|` 分隔，**推荐写文档 ID**（替换文档 ID 不变，用例长期有效）；也可写文档标题，但标题必须在本应用未删除文档中唯一——找不到或重名时整个文件拒绝导入并列出行号（`document_not_found` / `ambiguous_title`），库中只保存 `expected_document_ids`。`expected_intent` 为可选列（空 = 不评测意图）。
- 来源：业务人员整理的常见问题、真实会话日志、点踩反馈（反馈页"转评测用例"，带入问题与会话历史，`source=feedback`）、调试对话"加入评测集"（`source=debug`）。
- **意图用例**：每个应用另加 30–50 条，标注 `expected_intent`：寒暄 10–15（含变体与"你好，退货多久到账"这类混合句）、超出范围 8–10、含糊问题 5–8、要人工/投诉 5–8、业务办理 5–8、意图注入 3–5（见[意图识别 §12](../02-architecture/08-意图识别.md)）。
- **长对话用例**：每个应用至少 10 条 20 轮以上的多轮用例（存于 `eval_cases.history`），在早期轮次埋入订单号、型号、用户更正等细节，最后一问依赖这些细节，用于验证上下文压缩后不丢信息（见[对话上下文管理 §12](../02-architecture/07-对话上下文管理.md)）。评测运行时逐轮回放，压缩同步执行以保证可复现（见 §3）。

## 2. 指标（每题计算，再汇总）
| 指标 | 计算 | 需要 LLM 评判 |
|---|---|---|
| Recall@5 | 期望文档 ∈ 重排后前 5 的文档 | 否 |
| 引用命中率 | 期望文档 ∈ 实际引用 | 否 |
| 拒答准确率 | should_refuse 题中 answer_type ∈ {refused, handoff} 的比例 | 否 |
| 误拒率 | 可答题中被拒答的比例 | 否 |
| 答案正确率 | 评判模型对比期望答案输出 correct/incorrect | 是 |
| 忠实度 | 评判模型检查回答每个事实是否被引用支持（Ragas faithfulness 思路） | 是 |
| 细节保持率（长对话） | 最后一问的改写/回答正确使用早期埋入细节的比例 | 规则 + 是 |
| 改写正确率（长对话） | `rewritten_query` 与期望改写一致 | 是 |
| 意图准确率 | 有 `expected_intent` 的用例中实际意图一致的比例 | 否 |
| 寒暄误拒率 | `expected_intent=chitchat` 中 answer_type ∈ {refused, handoff} 的比例 | 否 |
| 误转人工率 | `expected_intent ∉ {human, action}` 中 answer_type=handoff 的比例 | 否 |
| 知识问答漏答率 | `expected_intent=kb_qa` 被判为其他意图的比例 | 否 |
| P50/P95 延迟、平均 token | | 否 |

> `answer_type=error` 的用例在所有指标中按失败计（不可答题也不算"拒答正确"），并在报告中单独列出错误数。

评判模型默认与对话模型相同（DeepSeek），温度 0，提示词存于 `modules/eval/prompts/eval_judge.md`（带 front-matter 版本）。LLM 评判有误差，指标变化 < 3 个百分点视为噪声。

## 3. 运行
- 执行方式：`run_eval` 任务（队列 `eval`）对每条用例调用与线上完全相同的 `chat.service.handle_turn()`，`run_mode=eval`：
  - 每条用例新建一个 `channel=eval` 会话（不计入统计、会话日志默认不显示）；多轮用例按 `history` 逐轮回放并落库，最后一问的结果计分；
  - 压缩**同步**执行（不投递 `context` 队列），保证同一输入可复现；
  - trace 写入 `eval_results.trace`，不推送；
  - 运行开始记录 `config_snapshot`（含 overrides）、`prompt_versions`（全部提示词 `{name: version}`）与 `llm_model`；每题记录 `prompt_version`。对比两次运行时，配置或提示词版本不同会在报告中高亮。
  - 应用进入 `deleting` 时运行中止（`cancelled`）。
- 后台：评测页点击"运行评测"（可设临时参数覆盖）。
- 命令行：`uv run aics-cli eval --app <app_id> --set <set_id> [--override rag_config.rerank_threshold=0.4]`，结果写库并输出 Markdown 报告到 `eval_reports/`（gitignore）。

## 4. 调参顺序（建议）
1. 先看 Recall@5：低 → 检查切块预览是否切坏、调 `chunk_size`、加自定义词典、调 top_k。
2. 再看误拒率 / 拒答准确率：用评测结果中每题的 top rerank 分数分布，选择能最好区分"可答 / 不可答"的 `rerank_threshold`。
3. 最后看正确率与忠实度：调提示词、`answer_style`、温度。
3.1 长对话细节保持率低 → 调 `history_token_budget`、`compact_trigger_tokens`、`keep_recent_turns`，或开启 `enable_history_recall`（`enable_facts` 默认已开启）；保持率 / 更新正确率 / 混淆率（[对话上下文管理 §12.2](../02-architecture/07-对话上下文管理.md)）异常时检查事实抽取与对账；修改摘要或事实抽取提示词后必须重跑长对话用例。
3.2 意图指标异常 → 漏答率高则提高 `min_confidence` 或收紧 `chitchat_max_chars`；误转人工率高则检查 `handoff_config.keywords` 是否有易误触的短词；修改 `condense_classify` 提示词后必须重跑意图用例。
4. 每次只改一个变量，记录 `config_version`、`prompt_versions` 与运行 ID。

## 5. 发布门槛
`dev` → `main` 前，对样例评测集运行一次，任何指标比上一版本下降 > 5 个百分点需说明原因。

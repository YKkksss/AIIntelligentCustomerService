## 1. 项目概览
AICS（AI Intelligent Customer Service）是内网部署的 RAG 智能客服平台：管理员按"应用"建知识库，第三方系统用 API Key 调对话接口（原生 + OpenAI 兼容），答不了时转人工，并通过 Webhook / 事件流与接入方的坐席平台联动。
- 后端：Python 3.12 + uv、FastAPI、SQLAlchemy 2 async + asyncpg + Alembic、Celery 5（RabbitMQ broker，队列 `ingest` / `context` / `eval` / `maintenance`，beat）、Redis、Qdrant、LangGraph。
- 模型：DeepSeek（`deepseek-flash`，OpenAI 兼容）做对话；阿里云百炼 `qwen3.7-text-embedding-flash`（1024 维）做向量化、`qwen3.7-text-rerank` 做重排。
- 前端：Vue 3 + Vite + TypeScript + Element Plus + Pinia（目前只有骨架，M4 实现）。
- 背景与范围：[项目概述](../00-planning/01-项目概述.md)、[范围定义](../00-planning/02-范围定义.md)、[功能需求](../01-requirements/01-功能需求.md)、[非功能需求](../01-requirements/02-非功能需求.md)。

## 3. 编码约定（详见[编码规范](../06-development/03-编码规范.md)）
- **代码注释、docstring、标识符用英文；文档用中文；提交信息用中文 Conventional Commits**（`feat(chat): M3.3 OpenAI 兼容接口阻塞模式`）。旧代码里的中文注释不批量翻译，改到哪里顺手改。
- 分层：router 只做参数与响应 → service 写业务 → repository 写 SQL。依赖方向由 import-linter 检查（13 个合同，`backend/pyproject.toml`），关键规则：
  - L0 `core` → L1 `db` / `providers` / `vectorstore` / `storage` → L2 `ingest` / `memory` / `rag` → L3 `modules.*` → L4 `main` / `tasks` / `cli`，只能向下依赖。
  - `rag` 不 import `db`、`modules`、`memory`、FastAPI，只经 `rag.ports`；`memory` 不 import `rag`。
  - `main`、`tasks`、`cli` 互不 import，投递任务一律按任务名 `send_task`。
  - 业务模块之间只允许 `chat → apps / webhooks`、`handoff → chat / webhooks / apps`、`eval → chat`、`feedback → eval`（ADR-0017，M3.4 改合同）。
  - 横切能力（API Key 鉴权、后台权限、审计）在 `core` 定义 Protocol，由模块实现、`main` 注入到 `app.state`。
- 带 `app_id` 的表的 repository 继承 `AppScopedRepository`，方法第一个参数是 `app_id`；跨应用方法名必须以 `_all_apps` 结尾（单元测试会遍历检查）。
- token 只用 `core.tokens.count_tokens`；分词只用 `core.textsearch`；配置只用 `get_settings()`；提示词只放 `*/prompts/*.md`（改正文 +1 `version`）。
- 状态迁移一律"带条件的单行更新"（compare-and-set），影响 0 行即冲突；不靠分布式锁。

## 4. 开发流程（每个子步骤）
1. **计划**：在[开发计划](../00-planning/03-开发计划.md)对应行下写子步骤计划（①②③…，每项一个可独立提交的单元），以[后续里程碑详细计划](../00-planning/06-后续里程碑详细计划.md)为蓝本，有出入就改蓝本。
2. **实现**：每个单元一个提交。提交前在 `backend/` 下跑完与 CI 相同的检查：
   ```bash
   uv run ruff check . && uv run ruff format --check .
   uv run lint-imports
   uv run python -m aics.core.prompts check
   uv run pytest --cov=aics --cov-fail-under=80        # 只跑单元测试（默认排除 integration / live）
   AICS_TEST_DB_URL=… AICS_TEST_QDRANT_URL=:memory: uv run pytest -m integration   # 动到数据库 / 检索时
   ```
   前端改动另跑 `npm run lint && npm run build`（M4.1 起加 `npm run test -- --coverage`）。
3. **覆盖率门槛**：CI 要求全包单元测试覆盖率 ≥ 80%，当前 80.58%，余量很小。**每个提交的新代码都要自带单元测试**；只能靠集成测试覆盖的代码（如 SQL）也要有集成测试，但它不计入门槛，所以 service 层逻辑尽量用假实现写单元测试（参考 `tests/chat_support.py`、`tests/fake_redis.py`、`memory_store_contract.py`）。
4. **测试文档要长、要真实**：解析、切块、记忆、评测用的测试文档和对话要接近真实业务长度（几千到几万字、20 轮以上），不要用两三句话的玩具样例。虚构公司"星河优选"语料在 `backend/scripts/e2e_m1/`，长对话样本在 `backend/scripts/e2e_m2/memory_cases.json`。
5. **记录**（同一子步骤内完成）：
   - 测试结果写入本里程碑测试报告（M1–M2 在 `08-M1端到端测试报告.md`；M3 起 `10-M3测试报告.md`、`11-M4…`）；
   - 测试支持的最佳值写入[参数默认值与依据](../06-development/09-参数默认值与依据.md)，同步代码与设计文档；
   - 有取舍就写设计讨论（下一个编号 0010），重要决策另写 ADR（下一个 0018）；
   - 开发计划打 ✅ 并写一段状态说明；更新[实现现状](02-实现现状与代码地图.md)；CHANGELOG `[Unreleased]` 追加；
   - 服务器才能验证的项加进待复验清单。
6. **汇报**：每个子步骤结束，给大老板一段报告：做了什么（提交列表）、测试结果、真实模型花费、新增的待复验项、下一步。
7. **里程碑结束**：写里程碑总结（开发计划中），列交付、质量、未达标 / 遗留、费用、tag 状态。

## 5. 大老板的常设规则
1. 每轮测试结果都记录进文档，测试最好的取值采纳为默认值，写进[参数默认值与依据](../06-development/09-参数默认值与依据.md)。
2. 每个值得记录的选择写设计讨论：借鉴了什么、为什么；补充了什么；**不借鉴**什么、为什么；在哪个子步骤落地（[设计讨论 README](../09-design-discussions/README.md) 有固定结构）。
3. 外部建议（包括 AI 评审意见）有选择地采纳，不照单全收；文档没写的细节，按业界通行做法补上，并写进文档。
4. 测试用长的、真实的文档。
5. **记忆功能非常重要**：任何改动都不能让长对话评测（保持率、混淆率、标识符陷阱）退化；动到 `memory` / `load_context` / 压缩 / 事实时必须重跑 `scripts/e2e_m2/eval_m25.py`。
6. 破坏性操作（删数据、删集合、force push、重置分支、改服务器配置、部署）**先问大老板**。
7. 密钥绝不进仓库。真实密钥只在盒子的 `~/.aics/secrets.env`（chmod 600）和开发机 / 服务器的 `.env`；文档与示例只用占位符；不在日志或报告里打印密钥。
8. 真实模型花费：每个子步骤 < 1 元（超出要在计划里写理由），累计到 3 元必须停下来报告。
9. 推送到用户仓库前要得到明确授权；没有授权时只在盒子上提交，用 `git format-patch` 交付。

## 7. 模型与费用
| 用途 | 模型 | 价格（元 / 百万 token，输入 / 输出） | 说明 |
|---|---|---|---|
| 对话、分类、judge、摘要、事实抽取、评判 | `deepseek-flash` | 2 / 8 | 短调用固定关闭思考；generate 由 `llm_thinking` 控制（默认关） |
| 向量化 | `qwen3.7-text-embedding-flash`（1024 维） | 0.125 | 改模型或维度需全量重建 |
| 重排 | `qwen3.7-text-rerank` | 0.5 | 质量的主要来源，默认开启 |

经验值：一轮带检索的问答 ≈ 0.01–0.015 元；20 轮长对话（含压缩）≈ 0.1 元；50 题评测（含两次 LLM 评判）≈ 1.1 元。M1 + M2 真实模型合计约 9.5 元（其中 M2.2b 生成评测问题 5.35 元）。

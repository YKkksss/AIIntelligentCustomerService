# 接口规范

## 1. 基础
| 项 | 约定 |
|---|---|
| 基础地址 | 开发 `http://localhost:8000`；内网生产 `http://192.168.110.86:8080`（Nginx） |
| 开放接口 | `/api/v1/...`（API Key） |
| 管理接口 | `/api/v1/admin/...`（JWT） |
| OpenAI 兼容 | `/v1/chat/completions`、`/v1/models`（API Key） |
| 文档 | `/docs`（Swagger）、`/openapi.json`；**生产环境（`AICS_ENV=prod`）整体关闭**（`docs_url` / `redoc_url` / `openapi_url` 都是 `None`），接口清单以本目录文档为准；非生产环境开放 |
| 格式 | JSON，UTF-8；字段 `snake_case`；时间 ISO 8601 带时区（`2026-10-14T17:00:00+08:00`） |
| ID | UUID 字符串 |
| 版本 | 路径版本 `v1`；同一大版本内只做向后兼容的新增；破坏性变更走 `v2` 并保留 v1 至少 6 个月 |

## 2. 鉴权
- **开放接口**：`Authorization: Bearer aics_<32位随机>`。Key 绑定一个应用，路径中的 `app_id` 必须与 Key 所属应用一致，否则 `404`（不暴露资源存在性）。
- **管理接口**：`Authorization: Bearer <JWT access token>`；access 30 分钟，refresh 默认 1 天、登录时可选 7 天（`remember_days`；刷新时轮换并沿用所选天数，旧 refresh 失效）。
- 权限检查：API Key scope（`chat`、`kb:read`、`kb:write`、`handoff:write`）或后台 RBAC 权限（`app.read`、`kb.write` 等点分名称）不足 → `403 FORBIDDEN`。两套名称的完整清单见[安全设计 §2.1](../08-security/01-安全设计.md)。
- 应用处于 `deleting` 时，开放接口与后台接口一律 `404 APP_NOT_FOUND`。

## 3. 统一响应
成功：直接返回资源对象或列表包装，不再套 `{"code":0,"data":...}`（符合 OpenAPI 习惯）。
错误：
```json
{
  "error": {
    "code": "DOCUMENT_NOT_FOUND",
    "message": "文档不存在",
    "details": {"document_id": "..."},
    "request_id": "01J..."
  }
}
```

## 4. 错误码
> 代码中的取值见 `core/errors.py` 与各模块的 `AppError` 子类；M3.6 起有单元测试比对本表与代码，二者必须一致（`backend/tests/unit/test_error_codes.py`：双向比对 + 状态码对齐 + 未实现码显式列在 `PENDING` 里）。已实现的码（M2）：`VALIDATION_ERROR`、`UNSUPPORTED_FILE_TYPE`、`URL_NOT_ALLOWED`、`PARSE_FAILED`、`UNAUTHENTICATED`、`API_KEY_EXPIRED`、`API_KEY_REVOKED`、`FORBIDDEN`、`APP_DISABLED`、`NOT_FOUND`、`APP_NOT_FOUND`、`DOCUMENT_NOT_FOUND`、`CHUNK_NOT_FOUND`、`QUESTION_NOT_FOUND`、`CONVERSATION_NOT_FOUND` / `KNOWLEDGE_BASE_NOT_FOUND`、`KNOWLEDGE_BASE_NOT_FOUND`（M4.7）、`CONFLICT`、`DOCUMENT_BUSY`、`DUPLICATE_DOCUMENT`、`CONVERSATION_CLOSED`、`FACT_EXISTS`、`FACT_NOT_FOUND`、`RATE_LIMITED`、`QUOTA_EXCEEDED`、`INTERNAL_ERROR`、`UPSTREAM_ERROR`、`UPSTREAM_UNAVAILABLE`、`SERVICE_UNAVAILABLE`、`UPSTREAM_TIMEOUT`、`IP_NOT_ALLOWED`（M3.1）、`FILE_TOO_LARGE`、`IDEMPOTENCY_CONFLICT`（M3.2）；`HANDOFF_STATE_CONFLICT`（M3.4）、`METHOD_NOT_ALLOWED`（M3.6）、`TOKEN_EXPIRED` 与 `ACCOUNT_LOCKED`（M4.1 ②）、`CONFIG_VERSION_CONFLICT`（M4.2 ②）、`CALLBACK_STATE_CONFLICT`（M4.5 ③）、`KNOWLEDGE_BASE_NAME_TAKEN` / `KNOWLEDGE_BASE_IN_USE`（M4.7 ③）。表中所有码均已实现，`PENDING` 目前为空。

| HTTP | code | 说明 |
|---|---|---|
| 422 | `VALIDATION_ERROR` | 请求体/参数/配置校验失败，`details.errors` 列出字段（全系统统一用 422） |
| 400 | `UNSUPPORTED_FILE_TYPE` / `URL_NOT_ALLOWED` | 上传与 URL 导入 |
| —（不作为响应） | `PARSE_FAILED` | 入库任务解析失败，写入 `documents.error` 与 job，文档 `failed`；接口不会直接返回 |
| 401 | `UNAUTHENTICATED` | 缺少或无效凭证 |
| 401 | `API_KEY_EXPIRED` / `API_KEY_REVOKED` | |
| 401 | `TOKEN_EXPIRED` | JWT 过期，前端应刷新 |
| 403 | `FORBIDDEN` / `APP_DISABLED` / `IP_NOT_ALLOWED` | scope 不足（`details.required_scope`）；应用停用；Key 的 IP 白名单不含客户端地址（`details.client_ip`，M3.1） |
| 404 | `NOT_FOUND`、`APP_NOT_FOUND`、`DOCUMENT_NOT_FOUND`、`CHUNK_NOT_FOUND`、`QUESTION_NOT_FOUND`、`CONVERSATION_NOT_FOUND` / `KNOWLEDGE_BASE_NOT_FOUND` | 后三个用于知识库接口（切块、补充问题）；`KNOWLEDGE_BASE_NOT_FOUND` 用于公共知识库（M4.7） |
| 405 | `METHOD_NOT_ALLOWED` | 路由存在但方法不允许（如对 `/chat` 发 GET），带 `Allow` 头（M3.6 ⑤；Starlette 自己的 405 也走统一错误体） |
| 409 | `CONFLICT` / `IDEMPOTENCY_CONFLICT` / `DOCUMENT_BUSY` / `DUPLICATE_DOCUMENT` / `CONVERSATION_CLOSED` / `HANDOFF_STATE_CONFLICT` / `CALLBACK_STATE_CONFLICT` / `CONFIG_VERSION_CONFLICT` / `KNOWLEDGE_BASE_NAME_TAKEN` / `KNOWLEDGE_BASE_IN_USE` / `FACT_EXISTS` / `FACT_NOT_FOUND` | 首次请求处理中；同 Key 不同请求体；文档构建中或删除中不能重建/替换；替换的新文件与同应用另一文档重复（`details.document_id`）；会话已关闭（**仅人工坐席接口返回**，对话接口会自动新建会话）；转人工状态不允许该操作；应用配置已被他人修改（`details.expected` / `details.current`，M4.2）；事实乐观写冲突（`FACT_*`，后台编辑事实时，M4.5）；重复标记同一条待回访（`details.needs_callback`，M4.5 ③）；库名重复，或库里还有文档 / 仍被客服关联（M4.7 ③） |
| 413 | `FILE_TOO_LARGE` | 上传超过 `AICS_UPLOAD_MAX_MB`（M3.2；HTTP 入口在分块读取时立即拒绝，不把整个文件读进内存；M3.6 ⑤ 起服务层的同一条件也报这个码，两个入口一致） |
| 423 | `ACCOUNT_LOCKED` | 登录锁定 |
| 429 | `RATE_LIMITED` / `QUOTA_EXCEEDED` | 带 `Retry-After` |
| 500 | `INTERNAL_ERROR` | |
| 502 | `UPSTREAM_ERROR` | 模型供应商返回错误 |
| 503 | `UPSTREAM_UNAVAILABLE` / `SERVICE_UNAVAILABLE` | 熔断或依赖不可用 |
| 504 | `UPSTREAM_TIMEOUT` | |

> **OpenAI 兼容接口的错误体不同**（M3.3）：`/v1/*` 返回 `{"error":{"message","type","code"}}`。[`openai.py`](../../backend/src/aics/modules/chat/openai.py) 的映射表——`type` 按状态类：400 / 404 / 405 / 409 / 413 / 422 → `invalid_request_error`，401 → `authentication_error`，403 → `permission_error`，429 → `rate_limit_error`，5xx → `api_error`（`error_type`）；`code` 取业务码小写，两处特殊映射：`APP_NOT_FOUND` → `model_not_found`（`model` 与 Key 所属应用不一致）、`CONVERSATION_NOT_FOUND` / `KNOWLEDGE_BASE_NOT_FOUND` → `conversation_not_found`（`X-AICS-Conversation-Id` 不是本应用的会话）、`VALIDATION_ERROR` → `invalid_request`（与请求体解析分支同码）。原生 `/api/v1/...` 接口不受影响，仍是上面的 `{"error":{code,message,details,request_id}}`；四处异常处理器（`AppError` / `RequestValidationError` / `StarletteHTTPException`（404、405，其余原样返回）/ 兜底）按 `request.url.path` 前缀分流。

## 5. 分页
游标分页（日志类大表）：`?limit=20&cursor=<opaque>` → `{"items":[...],"next_cursor":"..."|null}`。
页码分页（后台小表）：`?page=1&page_size=20` → `{"items":[...],"total":123,"page":1,"page_size":20}`。`limit/page_size` 最大 100。
排序：`?sort=-created_at`。

## 6. 限流
- 每个 Key：`rpm_limit`（默认 60）令牌桶 + `daily_quota`；Redis key `aics:rl:{key_id}:{minute}`、`aics:quota:{key_id}:{yyyymmdd}`。
- 每个 IP（未认证请求，如登录）：10 次/分钟。
- 响应头：`X-RateLimit-Limit`、`X-RateLimit-Remaining`、`X-RateLimit-Reset`；超限 429 + `Retry-After`。

## 7. 幂等
- 写接口（上传、URL 导入、创建评测运行）支持 `Idempotency-Key: <客户端生成 UUID>`。
- 服务器以 `aics:idem:{key_id}:{Idempotency-Key}` 缓存 24 小时：相同请求体（SHA-256）返回首次结果；不同请求体 → `409 IDEMPOTENCY_CONFLICT`；首次仍在处理 → `409 CONFLICT`。
- 实现（M3.2，`core/idempotency.py`）：先写 `{"state":"processing","sha":…}` 占位，成功后覆写成 `{"state":"done","status":…,"body":…}` 供回放；**非 2xx 与异常一律删占位**（客户端可立即重试）；Redis 不可用时**放行**并记警告（上传仍有内容哈希去重兜底）。摘要口径：multipart 取「文件 SHA-256 + 其它字段的规范 JSON」，JSON 请求取规范化后的整体。键长上限 128 字符（超长 422），回放响应体上限 64 KB（超限只回放 `id`）。
- 对话接口不做幂等（每次都是新回答）。

## 8. 其他
- `X-Request-ID`：客户端可传，服务端回写；排查问题时提供给管理员。
- `X-AICS-Conversation-Id`：仅 OpenAI 兼容接口使用，把请求关联到服务端会话，规则见[开放接口参考 §3](02-开放接口参考.md)。
- 超时建议：阻塞对话客户端超时 ≥ 60s；SSE 每 15 秒发送 `: ping` 注释行保持连接。
- CORS：仅允许 `AICS_CORS_ORIGINS`；开放接口建议服务端到服务端调用，不要把 Key 放在浏览器。

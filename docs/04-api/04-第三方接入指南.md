# 第三方接入指南

> **实现状态（2026-10-19）**：对话接口（阻塞 / SSE、会话、消息）自 M2.6 起可用；知识库接口在 M3.2、OpenAI 兼容在 M3.3、转人工坐席接口在 M3.4、**Webhook 投递与会话事件流在 M3.5 上线**（§7 的格式、签名与退避已按实现核对，M3.5 ⑤ 用示例接收端 `backend/scripts/e2e_m3/webhook_receiver.py` 跑通了 26 项判定）。生成/轮换密钥、测试投递与投递记录查询等**管理接口在 M4.5**，当前可用 `POST /apps/{app_id}/webhook/...` 对应的后台页面尚在 M4.5 一并交付。M3.6 起本文示例写成自动化测试，保证可直接运行。

## 1. 接入步骤
1. 找平台管理员创建应用并上传资料（或自己用 `kb:write` Key 通过接口上传）。
2. 在后台「API Key」页创建 Key，**立即复制保存**（只显示一次），记下应用 ID。
3. 用下面的示例调通，再接入你的系统。
4. **Key 只放在服务端**，不要写进网页或 App 安装包。浏览器需要直接调用时，请经你自己的后端转发。

## 2. curl
```bash
export AICS_BASE=http://192.168.110.86:8080
export AICS_KEY=aics_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
export AICS_APP=<app_id>

# 阻塞
curl -s "$AICS_BASE/api/v1/apps/$AICS_APP/chat" \
  -H "Authorization: Bearer $AICS_KEY" -H "Content-Type: application/json" \
  -d '{"question":"退货要多久到账？","user_id":"u_10086"}'

# 流式（-N 关闭缓冲）
curl -N "$AICS_BASE/api/v1/apps/$AICS_APP/chat" \
  -H "Authorization: Bearer $AICS_KEY" -H "Content-Type: application/json" \
  -d '{"question":"退货要多久到账？","stream":true}'

# 上传资料
curl -s "$AICS_BASE/api/v1/apps/$AICS_APP/documents" \
  -H "Authorization: Bearer $AICS_KEY" -H "Idempotency-Key: $(uuidgen)" \
  -F "file=@售后政策.pdf"
```

## 3. Python（httpx，原生接口 + 流式）
```python
import json, os, httpx

BASE, KEY, APP = os.environ["AICS_BASE"], os.environ["AICS_KEY"], os.environ["AICS_APP"]
headers = {"Authorization": f"Bearer {KEY}"}

def ask(question: str, conversation_id: str | None = None) -> dict:
    r = httpx.post(f"{BASE}/api/v1/apps/{APP}/chat", headers=headers, timeout=60,
                   json={"question": question, "conversation_id": conversation_id})
    r.raise_for_status()
    return r.json()

def ask_stream(question: str):
    with httpx.stream("POST", f"{BASE}/api/v1/apps/{APP}/chat", headers=headers, timeout=60,
                      json={"question": question, "stream": True}) as r:
        r.raise_for_status()
        event = None
        for line in r.iter_lines():
            if line.startswith("event:"):
                event = line[6:].strip()
            elif line.startswith("data:"):
                data = json.loads(line[5:])
                if event == "delta":
                    print(data["text"], end="", flush=True)
                elif event == "end":
                    print("\n", data)
                elif event == "error":
                    raise RuntimeError(data)

res = ask("退货要多久到账？")
print(res["answer"], res["citations"])
if res["handoff"]:
    ...  # 转给你们的人工客服系统
ask("那运费谁出？", res["conversation_id"])  # 续聊
```

## 4. Python（OpenAI SDK，零改造接入）
```python
from openai import OpenAI
client = OpenAI(base_url="http://192.168.110.86:8080/v1", api_key="aics_xxx")
resp = client.chat.completions.create(model="<app_id>",
    messages=[{"role": "user", "content": "退货要多久到账？"}])
print(resp.choices[0].message.content)
print(resp.model_extra["aics"]["citations"])   # 引用在扩展字段

# 需要服务端记住多轮上下文：把上一轮返回的会话 ID 通过请求头带回（不带则为无状态，历史取自 messages）
# 注意：不带头的请求是无状态轮次，它建出的会话在该轮结束即关闭（不占会话表），
#       所以**首轮**返回的 ID 只用于排障；从「带过头的那一轮」起返回的 ID 才能一路续下去。
conv_id = resp.model_extra["aics"]["conversation_id"]
resp2 = client.chat.completions.create(model="<app_id>",
    messages=[{"role": "user", "content": "那运费谁出？"}],
    extra_headers={"X-AICS-Conversation-Id": conv_id})
# resp2 的会话 ID 才是真正保留的：下一轮把它带回，就会续在同一个会话上
conv_id = resp2.model_extra["aics"]["conversation_id"]

for chunk in client.chat.completions.create(model="<app_id>", stream=True,
        messages=[{"role": "user", "content": "退货要多久到账？"}]):
    print(chunk.choices[0].delta.content or "", end="")
```
LangChain 中：`ChatOpenAI(base_url=".../v1", api_key="aics_xxx", model="<app_id>")`。

## 5. JavaScript / Node 18+（fetch 读取 SSE）
```js
const res = await fetch(`${BASE}/api/v1/apps/${APP}/chat`, {
  method: "POST",
  headers: { Authorization: `Bearer ${KEY}`, "Content-Type": "application/json" },
  body: JSON.stringify({ question: "退货要多久到账？", stream: true }),
});
const reader = res.body.pipeThrough(new TextDecoderStream()).getReader();
let buf = "";
for (;;) {
  const { value, done } = await reader.read();
  if (done) break;
  buf += value;
  let i;
  while ((i = buf.indexOf("\n\n")) >= 0) {        // 事件以空行分隔
    const raw = buf.slice(0, i); buf = buf.slice(i + 2);
    const ev = /^event: (.*)$/m.exec(raw)?.[1];
    const data = /^data: (.*)$/m.exec(raw)?.[1];
    if (!data) continue;                          // 心跳
    const obj = JSON.parse(data);
    if (ev === "delta") process.stdout.write(obj.text);
    if (ev === "end") console.log("\n", obj);
  }
}
```
> 浏览器原生 `EventSource` 只支持 GET，不能带 Authorization 头，所以使用 fetch 方式（或 `@microsoft/fetch-event-source`）。

## 6. 接入建议
- **处理 answer_type**：`answer` 正常展示并显示引用；`refused` 展示话术并提供"转人工"按钮；`handoff` 表示本轮触发了转人工：坐席平台会收到 Webhook `handoff.requested`（§7），之后按 `reply_by` 展示回复（`ai` / `system` / `none`=等待人工回复，从会话事件流或消息列表获取）。`error` 只会出现在历史消息列表中（表示该轮生成失败），对话接口出错时返回错误体。
- **重试**：仅对 429（按 `Retry-After`）、502/503/504 重试，最多 2 次；400/401/403/404/409/422 不要重试。
- **会话**：保存 `conversation_id` 与你的用户会话关联；会话空闲超过应用配置的时间（默认 10 分钟）后关闭，关闭前 1 分钟会推送提醒（默认"如果没有其他问题，当前服务就结束咯~"）。用旧 ID 继续发消息时服务端自动新建会话，**响应中的 `conversation_id` 会变化**（`previous_conversation_id` 为旧 ID），请以响应为准更新。
- **实时消息**：需要在用户界面显示空闲提醒、人工回复时，订阅 `GET .../conversations/{id}/events`（SSE）或在服务端接收 Webhook。
- **反馈**：把用户的赞/踩回传，帮助我们改进准确率。
- 出问题时把响应头 `X-Request-ID` 发给管理员。

## 7. 出站 Webhook（转人工与会话事件）
接收地址与签名密钥在后台「应用配置 → Webhook」配置（管理接口与页面在 M4.5；在此之前由 `AppService.update_app` / `rotate_webhook_secret` 写入，示例见 `backend/scripts/e2e_m3/e2e_m35_webhooks.py`）。AICS 按以下**固定格式**推送，请让你的系统/坐席平台按此适配。设计细节见[会话生命周期与转人工](../02-architecture/09-会话生命周期与转人工.md)，payload 与 `GET …/events` 事件流**完全相同**（同一份构造器），因此同一套解析代码两处通用。

### 7.1 请求
```
POST <你的 URL>
Content-Type: application/json
X-AICS-Event: handoff.requested
X-AICS-Delivery: 0192f1a0-...        # = payload.id
X-AICS-Timestamp: 1792000000
X-AICS-Signature: sha256=<hex>
```
签名：`hex(HMAC_SHA256(secret, X-AICS-Timestamp + "." + 原始请求体))`。接收方必须校验签名，并拒绝时间戳与当前相差超过 5 分钟的请求。5 秒内返回 2xx 视为成功；否则按 10s、30s、2min、10min、30min 重试（共 6 次）。同一事件可能送达多次，请按 `id` 去重；同一会话按 `seq` 排序。

### 7.2 公共字段
```json
{
  "id": "0192f1a0-...",
  "event": "handoff.requested",
  "app_id": "0192f0c1-...",
  "conversation_id": "0192f0d2-...",
  "user_id": "u_10086",
  "seq": 7,
  "occurred_at": "2026-10-15T15:30:00+08:00",
  "data": { }
}
```
`user_id` 为接入方传入的用户标识（可能为 null）。

### 7.3 事件与 data
| event | data |
|---|---|
| `handoff.requested` | `{"reason":"intent_human","intent":"human","handoff_ai_mode":"wait","summary":"用户要求退货，询问运费是否报销，尚未解决","facts":{"order_no":"2026101400123"},"recent_messages":[{"id","role","kind","content","created_at"}]}`。`summary` 取会话滚动摘要渲染文本，无摘要时为最近一轮改写问题；`recent_messages` 为最近 10 条消息（旧→新）；`facts` 为原值（发往接入方自己的系统，接收方负责保护） |
| `handoff.accepted` | `{"agent_id","agent_name"}` |
| `handoff.released` | `{"agent_id","note","released_by":"agent"\|"admin"\|"system","reason":"agent"\|"admin"\|"accepted_idle"}`（`accepted_idle` = 接入后双方 `handoff_accepted_idle_minutes` 分钟无消息，随后会话关闭） |
| `handoff.queue_timeout` | `{"message":{...},"waited_seconds":300,"needs_callback":true}`：排队超过 `handoff_queue_timeout_minutes` 未接入，已退出排队并回到 AI；坐席平台应撤下该排队项，转入回访 |
| `handoff.offline` | `{"message":{...},"reason":"intent_human","needs_callback":true,"summary","facts","recent_messages"}`：非服务时间触发转人工，未排队，转为留言 |
| `message.created` | `{"message":{"id","role","kind","content","agent_id","answer_type","created_at"}}`；转人工 pending / accepted 期间的每条消息，以及任何时候的 system 消息 |
| `conversation.idle_notice` | `{"message":{...},"close_at":"2026-10-15T15:41:00+08:00"}` |
| `conversation.closed` | `{"reason":"idle"\|"handoff_idle"}` |

### 7.4 Python 校验示例
```python
import hmac, hashlib, time
def verify(secret: str, ts: str, body: bytes, sig: str) -> bool:
    if abs(time.time() - int(ts)) > 300:
        return False
    mac = hmac.new(secret.encode(), ts.encode() + b"." + body, hashlib.sha256).hexdigest()
    return hmac.compare_digest("sha256=" + mac, sig)
```
坐席平台收到 `handoff.requested` 后，用 `handoff:write` Key 调用开放接口 §5 的 accept / messages / release。

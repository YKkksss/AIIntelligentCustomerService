权限列：S = super_admin，A = 该应用 app_admin，V = 该应用 viewer。每个接口在代码中用 `require_perm("<RBAC 权限名>")` 声明，角色与权限的映射见[安全设计 §2.1](../08-security/01-安全设计.md)；本表的 S/A/V 是该映射的展开结果。

## 认证
| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| POST | `/auth/login` | 公开（按 IP 10 次/分钟） | `{"email","password"}` → `{"access_token","refresh_token","token_type":"bearer","expires_in":1800,"user":{...},"apps":[{app_id,app_name,role_id,permissions}]}`；未知邮箱、密码错误、账号禁用一律 401 `UNAUTHENTICATED`；连续失败 5 次 → 423 `ACCOUNT_LOCKED`（带 `Retry-After`） |
| POST | `/auth/refresh` | 公开（refresh 令牌） | `{"refresh_token"}` → 新的一对 token；refresh 一次性使用，已用过的再出现视为泄露 → 401 并踢掉全部设备 |
| POST | `/auth/logout` | 登录 | `{"refresh_token"}` → 204，删除该 refresh 的 jti（幂等，过期令牌也返回 204） |
| GET | `/auth/me` | 登录 | 当前用户 + 各应用角色与权限（super_admin 在所有应用里拿全量权限） |
| POST | `/auth/password` | 登录 | `{"current_password","new_password"}`（≥ 8 位）→ 新的一对 token；递增 `token_version`，旧 access 立即失效 |

`must_change_password=true` 的用户（新建、重置密码后）除 `GET /auth/me`、`POST /auth/password`、`POST /auth/logout` 外，访问任何管理接口一律 `403`，`details.reason = "must_change_password"`（代码里统一走 `core.security.ensure_password_changed`）。

## 用户与授权
| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| GET | `/users` | S（`user.admin`） | query `q`（邮箱或姓名模糊匹配）、`limit`（≤200，默认 100）→ `{"items":[{id,email,display_name,status,is_super_admin,must_change_password,last_login_at,created_at}]}` |
| POST | `/users` | S | `{"email","display_name","password","is_super_admin"?}` → 201 新用户，`must_change_password=true`；重复邮箱 409 `CONFLICT`；审计 `user.create` |
| GET/PATCH/DELETE | `/users/{user_id}` | S | PATCH 体 `{"display_name"?,"status"?,"is_super_admin"?,"password"?}`；改状态、改超管或改密都会递增 `token_version` 并清身份缓存（旧 access 立即失效）；审计 `user.update`，`diff` 里密码记 `***`。DELETE → 204，软删 + 禁用 + 递增 `token_version`，审计 `user.delete` |
| POST | `/users/{user_id}/reset-password` | S | → `{"password": 临时密码}`，**明文只返回这一次**；同时置 `must_change_password=true` 并递增 `token_version`（旧 access 立即失效），审计 `user.reset_password` |
| GET | `/apps/{app_id}/members` | S, A, V（`app.read`） | → `{"items":[{user_id,email,display_name,role_id,status}]}`，按邮箱排序 |
| PUT | `/apps/{app_id}/members/{user_id}` | S, A（`member.write`） | `{"role_id":"app_admin"\|"viewer"}`；用户或应用不存在 404；写审计 `member.set`，并立即失效该用户的身份与权限缓存 |
| DELETE | `/apps/{app_id}/members/{user_id}` | S, A | 204；不存在 404；审计 `member.remove`，同样立即失效缓存 |

## 调试对话（M4.4 ②④）
| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| POST | `/apps/{app_id}/debug/chat` | S,A,V | SSE；请求 `{"question":"…","conversation_id":"…"?,"debug_config":{…}?}`，`channel=debug` / `run_mode=debug` 由服务端写死 |

内部调用 `chat.service`（`RunMode.debug`）。viewer 可以使用：调试会话 `channel=debug`，**不视为修改操作**（不写审计）、不计入 `app_daily_stats` 与对外统计。`GET` 对没有 `app.write` 的成员（如 viewer）把正文、`citations` 与 `trace` 里的手机号 / 订单号打码（`138****5678`），应用成员读到原文。

所有示例：`BASE=http://localhost:8000`，`KEY=aics_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx`，`APP=0192f0c1-...`。

## 1. 对话
### POST /api/v1/apps/{app_id}/chat
scope：`chat`

请求：
```json
{
  "question": "退货要多久到账？",
  "conversation_id": null,
  "user_id": "u_10086",
  "stream": false,
  "metadata": {"channel": "app"}
}
```
| 字段 | 必填 | 说明 |
|---|---|---|
| question | 是 | 1–2000 字 |
| conversation_id | 否 | 续聊时传；不传则新建。不存在或不属于本应用 → `404 CONVERSATION_NOT_FOUND`；已关闭（空闲超时，按应用 `session_config.idle_close_minutes`，默认 10 分钟）→ **自动新建会话**处理本条消息，响应返回新 `conversation_id` 与 `previous_conversation_id`（新会话不继承旧历史），客户端应改存新 ID |
| user_id | 否 | 接入方用户标识，≤ 128 字符 |
| stream | 否 | 默认 false |
| metadata | 否 | ≤ 4KB，原样存储 |

阻塞响应 200：
```json
{
  "conversation_id": "0192f0d2-...",
  "previous_conversation_id": null,
  "message_id": "0192f0d2-...",
  "reply_by": "ai",
  "handoff_status": "none",
  "answer": "退货审核通过后，款项会在 3–5 个工作日原路退回 [1]。",
  "answer_type": "answer",
  "handoff": false,
  "handoff_reason": null,
  "intent": {"name": "kb_qa", "confidence": 0.86, "source": "llm"},
  "citations": [
    {"n": 1, "chunk_id": "0192...", "document_id": "0192...", "document_title": "售后政策.pdf",
     "heading_path": "售后政策 > 退款 > 到账时间", "snippet": "审核通过后 3-5 个工作日原路退回……",
     "score": 0.82, "page": 3}
  ],
  "usage": {"prompt_tokens": 1830, "completion_tokens": 64, "total_tokens": 1894},
  "latency_ms": 2310
}
```
`answer_type` 全系统统一枚举（数据库 `messages.answer_type`、评测结果、本接口相同）：
| 值 | 含义 | 出现位置 |
|---|---|---|
| `answer` | 正常回答（含寒暄、追问） | 对话响应、消息列表 |
| `refused` | 拒答（知识库无答案 / 超范围 / 敏感词），`answer` 为对应话术 | 对话响应、消息列表 |
| `handoff` | 需转人工，`answer` 为转人工话术 | 对话响应、消息列表 |
| `error` | 生成过程出错，本轮没有完整回答 | **只出现在消息列表与后台日志**；对话接口本身出错时返回错误体（阻塞）或 `event: error`（流式），不会返回 `answer_type=error` 的成功响应 |

`reply_by`：`ai`（AI 回答，`answer_type` 有值）/ `system`（系统话术，如 wait 模式等待提示，`answer_type=null`）/ `none`（坐席已接入，本轮无即时回复，`answer=null`，人工回复经会话事件流或消息列表获取）。`message_id` 为回复消息 ID；`reply_by=none` 时为本条 user 消息 ID。

`handoff`：**本轮**是否触发转人工；`handoff_status`：会话当前转人工状态 `none` / `pending` / `accepted` / `released`。转人工后的处理取决于应用 `handoff_ai_mode`（`continue`：坐席接入前 AI 继续回答；`wait`：AI 停止，回复等待话术），坐席接入后 AI 停止，坐席结束后恢复，详见[会话生命周期与转人工](../02-architecture/09-会话生命周期与转人工.md) §3。

`intent`：`name` 为 `kb_qa`（知识问答）、`chitchat`（寒暄，`answer_type=answer`）、`clarify`（`answer` 为追问问题，`answer_type=answer`）、`recall`（回问本次对话中提供过的信息，依据对话记忆回答，`answer_type=answer`，无引用）、`out_of_scope`（超出服务范围，`answer_type=refused`）、`human` / `action`（`answer_type=handoff`）、`blocked`（命中敏感词，`answer_type=refused`）；`source` 为 `rule`（规则层）/ `vector`（向量快速通道）/ `llm`（LLM 分类结果被直接采用）/ `fallback`（兜底链产生或意图识别关闭）。非 `kb_qa` 回复 `citations` 为空。`handoff_reason` 新增取值 `intent_human`、`intent_action`。详见[意图识别 §10](../02-architecture/08-意图识别.md)。

### 流式（stream=true）
响应 `Content-Type: text/event-stream`，事件依次为：
```
event: start
data: {"conversation_id":"0192f0d2-...","message_id":"0192f0d2-..."}

event: citations
data: {"citations":[{"n":1,"chunk_id":"...","document_id":"...","document_title":"售后政策.pdf","heading_path":"售后政策 > 退款 > 到账时间","snippet":"...","score":0.82,"page":3}]}

event: delta
data: {"text":"退货审核通过后，"}

event: delta
data: {"text":"款项会在 3–5 个工作日原路退回 [1]。"}

event: end
data: {"answer_type":"answer","handoff":false,"handoff_reason":null,"intent":{"name":"kb_qa","confidence":0.86,"source":"llm"},"used_citations":[1],"usage":{"prompt_tokens":1830,"completion_tokens":64,"total_tokens":1894},"latency_ms":2310,"reply_by":"ai","handoff_status":"none","previous_conversation_id":null,"answer":"签收后 7 天内可以无理由退货[1]。"}
```

`end` 事件携带最终 `answer`（引用清理后的全文，delta 已发出的内容无法撤回，以此为准）以及 `reply_by` / `handoff_status` / `previous_conversation_id`（M2.6）。
- 拒答 / 转人工时：没有 `citations`，`delta` 一次性给出话术，`end.answer_type` 为 `refused`/`handoff`。
- `reply_by=system`：`delta` 一次性给出系统话术；`reply_by=none`：`start` 后直接 `end`。`end` 均带 `reply_by`、`handoff_status`、`previous_conversation_id`。
- 寒暄 / 超范围 / 追问时：同样没有 `citations`，`end.intent.name` 标明意图。
- 出错：`event: error`，`data: {"code":"UPSTREAM_TIMEOUT","message":"...","request_id":"..."}`，随后关闭。
- `citations` 事件只在判定可答（kb_qa 且 judge 通过）之后、第一个 `delta` 之前发送一次，内容是送入生成的候选来源；最终实际引用以 `end.used_citations` 为准（阻塞响应的 `citations` 只含实际被引用的条目）。
- 客户端中途断开：服务端停止生成，已生成部分以 `interrupted=true` 落库。
- 心跳：`: ping` 注释行，客户端忽略即可。

### GET /api/v1/apps/{app_id}/conversations/{conversation_id}/messages
scope：`chat` 或 `handoff:write`。返回该会话消息（游标分页），用于回显历史与轮询。消息对象：`{id, role, kind, content, answer_type, handoff, intent, citations, agent_id, interrupted, created_at}`；`role` 为 `user` / `assistant` / `human_agent` / `system`，`kind` 为 `chat` / `idle_notice` / `idle_closed` / `handoff_wait` / `handoff_accepted` / `handoff_released`；`answer_type` 等回答字段只有 assistant 有值。响应附带会话对象 `{id, status, handoff_status, closed_at, previous_conversation_id}`。

### GET /api/v1/apps/{app_id}/conversations/{conversation_id}/events
（M3.5）scope：`chat` 或 `handoff:write`。会话事件流（SSE 长连接），推送 `message.created`（人工坐席与系统消息；转人工期间所有消息）、`handoff.requested/accepted/released`、`conversation.idle_notice`、`conversation.closed`；事件 `data` 与出站 Webhook 的 payload 完全相同（见[第三方接入指南 §7](04-第三方接入指南.md)），`id:` 行为会话事件序号 `seq`，重连时带 `Last-Event-ID` 补发。15 秒 `: ping`。会话关闭后推送 `conversation.closed` 并结束连接。用于终端用户界面实时收到空闲提醒和人工回复。

## 3. OpenAI 兼容
### GET /v1/models
返回该 Key 对应的应用：`{"object":"list","data":[{"id":"<app_id>","object":"model","owned_by":"aics"}]}`

### POST /v1/chat/completions
```json
{
  "model": "<app_id>",
  "messages": [
    {"role": "user", "content": "退货要多久到账？"},
    {"role": "assistant", "content": "……"},
    {"role": "user", "content": "那运费谁出？"}
  ],
  "stream": false,
  "user": "u_10086"
}
```
- 最后一条 `user` 消息为问题。客户端传的 `system` 消息**忽略**（应用配置为准，防止绕过规则）。
- **会话关联**（请求头 `X-AICS-Conversation-Id`）：
  - **不带**（默认，无状态）：历史 = 请求 `messages` 中最后一条 user 之前的 user/assistant 消息，按应用 `history_token_budget` + `keep_recent_turns` 裁剪（超预算且 `openai_temp_summary=true` 时请求内临时摘要），不使用服务端摘要/事实/回查。服务端为每个请求新建一个 `channel=openai` 会话，只写入本轮问答（用于日志与反馈），本轮结束即关闭（`close_reason=stateless`，不参与空闲提醒），响应 `aics.conversation_id` 返回该 ID，但它不会被自动用作下一次请求的历史。
  - **带**：值必须是本应用的会话 ID（可以是上一次响应的 `aics.conversation_id`，或原生接口创建的会话），否则 `404`（OpenAI 风格错误体，`code=conversation_not_found`）；会话已关闭 → 与原生接口相同，自动新建会话，`aics.conversation_id` 为新 ID、`aics.previous_conversation_id` 为旧 ID。转人工规则同原生接口：`reply_by=none` 时 `content` 为空字符串，`aics.reply_by` 标明。此时历史取自服务端会话（与原生接口完全相同），请求体中除最后一条 user 以外的消息被忽略。
  - `user` 字段写入 `conversations.external_user_id`，只用于日志筛选，不用于关联会话。
- 同样执行意图识别（历史取自请求 `messages`），寒暄、追问、超范围等话术放在 `choices[0].message.content`；客户端无法通过任何字段指定意图。
- `temperature`、`max_tokens` 可传，受应用配置上限约束；`tools` 等不支持的字段忽略。
- `model` 与 Key 所属应用不一致 → `404 model_not_found`（OpenAI 风格错误体 `{"error":{"message","type","code"}}`）。

响应：
```json
{
  "id": "chatcmpl-0192f0d2...",
  "object": "chat.completion",
  "created": 1792000000,
  "model": "<app_id>",
  "choices": [{"index": 0, "message": {"role": "assistant", "content": "运费由……[1]"}, "finish_reason": "stop"}],
  "usage": {"prompt_tokens": 1900, "completion_tokens": 50, "total_tokens": 1950},
  "aics": {"message_id": "...", "conversation_id": "...", "previous_conversation_id": null, "reply_by": "ai", "handoff_status": "none", "answer_type": "answer", "handoff": false, "intent": {"name": "kb_qa", "confidence": 0.86, "source": "llm"}, "citations": [ ... ]}
}
```
流式：标准 `data: {"object":"chat.completion.chunk",...}`，最后一个 chunk 在 `aics` 字段中带 `citations`、`answer_type`、`intent`，然后 `data: [DONE]`。

## 4. 知识库
| 方法 | 路径 | scope | 说明 |
|---|---|---|---|
| POST | `/api/v1/apps/{app_id}/documents` | kb:write | multipart：`file`、`title?`、`metadata?`(JSON 字符串) |
| POST | `/api/v1/apps/{app_id}/documents/url` | kb:write | `{"url":"https://...","title":null}` |
| GET | `/api/v1/apps/{app_id}/documents` | kb:read | `?status=done&q=关键字&page=1` |
| GET | `/api/v1/apps/{app_id}/documents/{document_id}` | kb:read | 含 status、progress、error、chunk_count |
| GET | `/api/v1/apps/{app_id}/documents/{document_id}/chunks` | kb:read | 分页；只返回生效版本的切块，含 `enabled`、`review_status` |
| PUT | `/api/v1/apps/{app_id}/documents/{document_id}/file` | kb:write | 替换文档（FR-KB-08），multipart `file`；文档 ID 不变；202 返回 job；新文件与本文档相同 → 200 `{"unchanged":true}`；与另一文档重复 → `409 DUPLICATE_DOCUMENT`；构建中 → `409 DOCUMENT_BUSY`。规则见[文档处理流水线 §5](../02-architecture/04-文档处理流水线.md) |
| POST | `/api/v1/apps/{app_id}/documents/{document_id}/reindex` | kb:write | 202；构建中或删除中 → `409 DOCUMENT_BUSY` |
| PATCH | `/api/v1/apps/{app_id}/documents/{document_id}` | kb:write | `{"title","metadata"}`；立即生效，无需重建 |
| DELETE | `/api/v1/apps/{app_id}/documents/{document_id}` | kb:write | 204；立即不可检索，异步清理 |

上传响应 202：
```json
{"id":"0192...","title":"售后政策.pdf","status":"queued","progress":0,"duplicate":false,"job_id":"0192..."}
```
重复文件 200 + `"duplicate": true`，返回已有文档。
`status` 取值：`queued`、`parsing`、`indexing`、`done`、`failed`、`deleting`；`index_version > 0` 时文档已有可检索的生效版本（构建或失败期间旧版本继续可用）。修改标题：`PATCH /api/v1/apps/{app_id}/documents/{document_id}`（kb:write，`{"title"}`，立即生效，无需重建）。

文档对象：
```json
{"id":"...","title":"售后政策.pdf","source_type":"file","mime_type":"application/pdf","size_bytes":523441,
 "version":2,"index_version":3,"pending_index_version":null,
 "status":"done","progress":100,"error":null,"chunk_count":42,"metadata":{},
 "created_at":"2026-10-14T17:00:00+08:00","updated_at":"2026-10-14T17:01:30+08:00"}
```

## 5. 人工坐席（转人工入站接口）
scope：`handoff:write`（给坐席平台单独建 Key，不要与对话 Key 共用）。状态机与业务规则见[会话生命周期与转人工](../02-architecture/09-会话生命周期与转人工.md) §3。
| 方法 | 路径 | 请求 | 说明 |
|---|---|---|---|
| GET | `/api/v1/apps/{app_id}/conversations/{conversation_id}/handoff` | — | `{"handoff_status","handoff_reason","requested_at","accepted_at","released_at","handoff_end_reason","needs_callback","agent_id","agent_name","handoff_ai_mode","in_service_hours"}` |
| POST | `.../handoff/accept` | `{"agent_id":"a_001","agent_name":"小王"}` | `pending → accepted`，200 返回状态 |
| POST | `.../handoff/messages` | `{"agent_id":"a_001","content":"您好，我是人工客服小王"}`（1–4000 字） | 仅 `accepted` 且为接入坐席；写 `role=human_agent` 消息，201 返回消息对象 |
| POST | `.../handoff/release` | `{"agent_id":"a_001","note":"已解决"}` | `pending` 或 `accepted` → `released`，AI 恢复 |
| GET | `/api/v1/apps/{app_id}/handoffs?status=pending` | — | 列出处于 pending / accepted 的会话（游标分页），供坐席平台补偿拉取 |

错误：状态不符 `409 HANDOFF_STATE_CONFLICT`（`details.handoff_status`）；`agent_id` 非接入坐席 `403 FORBIDDEN`；会话已关闭 `409 CONVERSATION_CLOSED`；会话不存在 `404 CONVERSATION_NOT_FOUND`。

## 6. 健康检查（无需鉴权）
- `GET /healthz` → `{"status":"ok"}`（进程存活）
- `GET /readyz` → `{"status":"ok","checks":{"postgres":"ok","redis":"ok","rabbitmq":"ok","qdrant":"ok"}}`；任一失败返回 503。

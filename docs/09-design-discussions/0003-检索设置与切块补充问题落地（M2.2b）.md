# 0003 检索设置与切块补充问题落地（M2.2b）
- 日期：2026-10-16
- 参与：开发（依据 M1 / M2.2 评测与负责人 M2.2b 任务说明）
- 相关：[设计讨论 0001](0001-知识库切块与检索设置-参考Dify.md)（A5、C2、C4、C5）、[ADR-0015 默认加权融合](../02-architecture/adr/0015-默认融合改为加权与切块补充问题.md)、[ADR-0004](../02-architecture/adr/0004-混合检索与RRF.md)、[M1 测试报告 §9–§10](../06-development/08-M1端到端测试报告.md)

## 1. 背景
0001 定下了 M2.2b 的范围（检索模式、融合方式、向量分数阈值、标签过滤、补充问题、命中测试），但没有定实现细节。M1 / M2.2 评测显示：全文路 Hit@1 只有 0.63，剩余未命中都是**词汇不匹配**（“专票”↔“增值税专用发票”、“多久到账”↔“15 个工作日”、“弄丢”↔“灭失”），去疑问词无效；RRF 等权融合（0.80）低于纯向量（0.88），离线加权 0.7 为 0.86。本次讨论确定落地方式和默认值，并用真实百炼 + DeepSeek 做网格评测。

## 2. 参考的业界做法
| 做法 | 出处 | 用法 |
| --- | --- | --- |
| 混合检索可选“权重 / rerank”，分数 min-max 归一后加权 | Dify 混合检索、Weaviate `relativeScoreFusion`、Elasticsearch linear retriever | 加权融合按路 min-max 归一后 `w·vec + (1−w)·kw` |
| 假设性问题索引（Hypothetical Questions / “多向量检索”）：为切块生成问题单独向量化，命中后返回原块 | LangChain MultiVectorRetriever、LlamaIndex QuestionsAnsweredExtractor、Dify Q&A 分段 | 补充问题单独成点、payload 指回 chunk |
| 同一向量集合混存多种点、用 payload 区分 | Qdrant 多租户 / payload 过滤实践 | `kind=question` 与切块同集合 |

## 3. 借鉴（ADOPT）
| # | 内容 | 收益 | 落地 |
|---|---|---|---|
| A1 | **加权融合**：每路命中在可检索性过滤后做 min-max 归一（单个命中记 1.0），`score = w·vec + (1−w)·kw`；同分按向量名次、再按 id | 向量路明显更强时不再被全文路拉平；RRF 仍可选 | M2.2b |
| A2 | **补充问题与切块同集合**：点 id = 问题 id，payload `kind=question`、`chunk_id` = 原切块；向量路按 chunk 取最高分去重 | 不新增集合与检索调用；禁用 / 复核 / 删除 / 标签同步天然覆盖问题点 | M2.2b |
| A3 | **问题单独向量化、不加标题前缀** | 问题要像用户提问才能和用户提问对齐；加“文档：…”前缀会把它拉回正文分布 | M2.2b |

## 4. 不借鉴（NOT ADOPT）
| # | 内容 | 理由 |
|---|---|---|
| N1 | **入库时自动用 LLM 为每个切块生成问题**（维持 0001 N2） | 评测（§6）显示：重排开启时没有增益（均为 1.0）；只在不重排时 Hit@1 +0.04；纯向量路反而下降（0.882→0.843，生成的泛化问题会把相近切块拉上来）；成本与耗时高（412 块 × 3 问，DeepSeek 推理 token 63 万 ≈ 5.3 元、约 10 分钟）。补充问题保持**人工维护**，`source=llm` 只用于评测或后续“LLM 建议 + 人工确认”。 |
| N2 | 独立的问题集合 / 第二次向量检索 | 多一次网络往返和一致性维护，收益为零（同集合 payload 区分即可） |
| N3 | 问题点在 PG 侧也建全文索引 | 补充问题解决的是语义改写；关键词路靠 `custom_dict` 与同义词（后续） |

## 5. 我们的补充（OUR ADDITIONS）
| # | 内容 | 落地 |
|---|---|---|
| C1 | **重建迁移**：构建切换后按“正文哈希相同、ordinal 最近”把问题挂到新构建的切块（只改 Qdrant payload，不重新向量化）；匹配不到 → `status=pending`、`chunk_id` NULL、删点，后台列出待确认、可重新挂接；迁移幂等，清理旧构建前再执行一次 | M2.2b |
| C2 | `chunk_questions.chunk_id` 用 **ON DELETE SET NULL**（数据库设计原写 CASCADE）：清理旧构建不能静默删掉运营录入的内容；文档删除时按 `document_id` 级联删除 | M2.2b |
| C3 | **标签过滤双重校验**：Qdrant payload `tags` 过滤之外，向量命中回 PG 取正文时再按 `documents.tags && :tags` 过滤；Qdrant 标签同步失败只会漏召回、不会串答 | M2.2b |
| C4 | 请求未带标签时使用 `rag_config.default_tags`；显式传 `[]` 表示不过滤 | M2.2b |
| C5 | Qdrant 原始 limit = `k × 2`（`VECTOR_OVERFETCH`），抵消陈旧点与同一切块多个问题点去重 | M2.2b |
| C6 | 集成测试支持 `AICS_TEST_QDRANT_URL=":memory:"`（qdrant-client 本地模式），无 Qdrant 服务器的开发机也能跑全部入库 / 检索集成测试 | M2.2b |

## 6. 评测（详见 M1 测试报告 §10）
51 道可答题，真实百炼向量 + 重排，DeepSeek 生成每块 3 个问题（1234 条）。重排开启时所有配置 Hit@1 = 1.0；不重排时：

| 融合 | 无补充问题 Hit@1 / MRR | 有补充问题 Hit@1 / MRR |
| --- | --- | --- |
| RRF | 0.804 / 0.856 | 0.804 / 0.865 |
| 加权 0.5 | 0.824 / 0.884 | 0.824 / 0.895 |
| 加权 0.6 | 0.843 / 0.899 | 0.882 / 0.924 |
| **加权 0.7** | **0.863 / 0.912** | **0.902 / 0.928** |
| 加权 0.8 | 0.863 / 0.909 | 0.863 / 0.907 |
| 加权 0.9 | 0.882 / 0.918 | 0.863 / 0.907 |

## 7. 最终决策
- 默认 `fusion=weighted`、`vector_weight=0.7`（不重排时最好、重排时与 RRF 持平；rerank 失败降级与 `enable_rerank=false` 的应用直接受益）；RRF 保留为选项。决策见 ADR-0015，修订 ADR-0004 的融合部分。
- `retrieval_mode` 默认 `hybrid`；`vector_score_threshold` 默认 null（本集无依据设阈值，命中测试页可按应用校准）。
- 补充问题：人工维护（服务方法 add / list / delete / reattach，HTTP 与页面随 M4.3 / M4.3b）；每块最多 20 条、每条 ≤ 200 字；不做入库自动生成。
- 命中测试：`KnowledgeService.hit_test` 只读，返回两路分数 / 名次、融合、rerank 分数与顺序。

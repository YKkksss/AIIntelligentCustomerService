# 0002 对话记忆方案（参考业界分层记忆）
- 日期：2026-10-16
- 参与：项目负责人（提供一份通用的“业界记忆架构”整理并评审取舍）、开发
- 相关：[ADR-0006 对话上下文分层管理](../02-architecture/adr/0006-对话上下文分层管理.md)、[ADR-0008 记忆模块与对话职责划分](../02-architecture/adr/0008-记忆模块与对话职责划分.md)、[ADR-0014](../02-architecture/adr/0014-对话记忆-关键事实默认开启与版本化.md)、[对话上下文管理](../02-architecture/07-对话上下文管理.md)

## 1. 背景
负责人整理的通用记忆架构（参考 Mem0、Zep / Graphiti、Letta / MemGPT、LangGraph Checkpointer + Store、ChatGPT 记忆）：
- **五层**：工作记忆（上下文窗口 + 压缩）、核心档案（每轮固定注入）、事实记忆（向量库）、情景摘要（带时间线）、原文归档（工具精确查找）。
- **写入**：异步抽取，带类型 / 重要度 / 时间 / 来源；与已有记忆对账，做 新增 / 合并 / 更新 / 删除（Mem0）。
- **读取**：固定注入 + 混合自动检索（按相关度 / 重要度 / 时近度排序）+ Agent 工具调用（Letta / MemGPT）。
- **维护**：版本化更新、衰减与整合、冷热分层。
- **安全**：用户可查看 / 修改 / 删除、按用户隔离、规则护栏、记忆评测（记住了没有 / 更新对不对 / 有没有张冠李戴）。

AICS 在此之前的方案（对话上下文管理 v0.2 + ADR-0006/0008）：原文全量保存；按 token 预算装入“关键事实 → 滚动摘要 → 近期原文”；超阈值异步压缩为结构化摘要；`conversation_facts`（键值 upsert、覆盖旧值）与会话内回查放在 M5，由评测决定是否默认开启；跨会话记忆不做。

## 2. 借鉴（ADOPT）
| # | 内容 | 收益 | 落地 |
|---|---|---|---|
| A1 | **事实带类型、重要度、来源、时间，并保留版本历史**：`conversation_facts` 增加 `category`、`importance`、`source`（slot / compaction）、`version`、`first_seen_at`；更新不再直接覆盖，旧值写入 `conversation_fact_history`（追加，不改不删）；对账操作 ADD / UPDATE / NOOP / RETRACT（用户明确否认时撤回，不物理删除） | 用户更正订单号后旧值可追溯（客服纠纷、排查“为什么答错”）；重要度决定预算紧张时谁先注入 | M2.1（表）、M2.5（逻辑） |
| A2 | **关键事实默认开启并每轮固定注入**（会话内的“核心档案”）：`order_no`、`phone`、`product`、`issue_type` 等；`enable_facts` 默认 `true`；`conversation_facts`、`capture_slots`、压缩时事实抽取从 M5 提前到 M2 | 客服场景最常见的失败是“刚说过的订单号又问一遍”；事实 < 300 token，成本可忽略 | M2.1（表）、M2.5（逻辑） |
| A3 | **会话内回查改为混合检索 + 时近度排序**：向量 + 关键词 RRF（k=60），再与时近度加权：`score = 0.8 × rrf/rrf_max + 0.2 × 0.5^(Δ轮次/10)` | 指代“刚才那个”时更近的提及优先，减少取回早已作废的旧说法 | M5（与消息向量化一起；公式与参数在 M5.4 评测校准） |
| A4 | **标识符一致性护栏（规则，不调 LLM）**：回答中出现订单号 / 手机号样式的字符串时，postprocess 与当前 facts 比对；不在 facts（也不在本轮用户消息、检索资料）中 → `degraded += ["identifier_mismatch"]`、记指标与 trace | 防止张冠李戴（把别的订单号说给用户）；零额外延迟 | **M2.5**（facts 在 M2.5 才进入 RagState，放在 M2.3 无数据可比；放到 M5 太晚） |
| A5 | **记忆评测指标**：保持率（早期事实在后续被正确使用）、更新正确率（更正后用新值）、混淆率（使用了别的会话 / 已作废的值） | 把“记住、记对、不混”量化，提示词与参数改动有回归依据 | M2.5（脚本化长对话评测）、M5.4（正式评测集） |

## 3. 不借鉴（NOT ADOPT）
| # | 内容 | 理由 |
|---|---|---|
| N1 | **跨会话核心档案 / 长期记忆** | v1 用户多为匿名访客，接入方不传稳定用户 ID；跨会话保存个人信息带来隐私与合规风险。列入 v2：接入方传入 `user_id` 后再评估（见范围定义 v2） |
| N2 | **Agent 自管理记忆（通过工具调用读写记忆，Letta / MemGPT）** | 每轮多一次或多次 LLM 往返，延迟与成本上升，行为难以预测与测试；客服场景用规则触发回查（指代词、`history_gap`）即可覆盖主要需求 |
| N3 | **知识图谱记忆（Zep / Graphiti）** | 单会话规模（几十轮、十余个事实）用键值 + 历史表足够；图谱带来抽取成本与运维复杂度 |
| N4 | **衰减与整合、冷热分层** | 记忆只在单个会话内有效，随会话保留策略（默认 180 天）整体清理；没有长期累积，不需要衰减与分层 |

## 4. 我们的补充（OUR ADDITIONS）
| # | 内容 | 收益 | 落地 |
|---|---|---|---|
| C1 | **`history_token_budget` 预算评测**：对比 3000 / 8000 / 16000（deepseek-flash 窗口 100 万，窗口不是约束），看保持率、改写正确率、首 token 时延与成本，按常设规则采纳最优值 | 默认预算有数据依据，而不是拍脑袋；大窗口模型可能“少压缩”更好 | M2.5（结果写入参数默认值与依据，当前标“待评测”） |
| C2 | **事实注入顺序与上限**：按 `importance` 降序、同级按 `updated_at` 新→旧，事实区上限 300 token；超出的低重要度事实不注入（仍保存） | 事实区不会挤占近期原文 | M2.5 |
| C3 | **RETRACT 只撤回不删除**：撤回的事实不注入、不参与护栏比对，历史表保留 | 审计与排障可追溯 | M2.5 |

## 5. 最终决策
- 采纳 A1–A5、C1–C3，不采纳 N1–N4；决策摘要见 [ADR-0014](../02-architecture/adr/0014-对话记忆-关键事实默认开启与版本化.md)（修订 ADR-0006 第 4 条）。
- 落地顺序：M2.1（`conversation_facts` + `conversation_fact_history` 表）→ M2.5（`capture_slots`、压缩时抽取与对账、固定注入、标识符护栏、预算评测与记忆指标脚本）→ M5（消息向量化、混合回查 + 时近度、正式长对话评测集与三项记忆指标）。

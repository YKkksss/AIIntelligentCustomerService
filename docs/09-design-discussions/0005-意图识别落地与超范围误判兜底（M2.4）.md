# 0005 意图识别落地与超范围误判兜底（M2.4）

- 日期：2026-10-16
- 状态：已采纳（M2.4）
- 相关：[意图识别](../02-architecture/08-意图识别.md)、[RAG 流程](../02-architecture/04-RAG流程.md)、[0004](0004-RAG图单轮实现取舍（M2.3）.md) P1、[M1 测试报告 §12](../06-development/08-M1端到端测试报告.md)

## 1. 背景
M2.3 冒烟中知识库内问题 q26（"实验数据集一共有多少条问答对？"）被 LLM 分类为 `out_of_scope`，不检索直接拒答；窄应用描述下 q39（仓储合同赔偿上限）也同样漏答。漏答比拒答更隐蔽（意图识别 §16），需要一个兜底。

## 2. 超范围误判兜底：候选方案
| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| A. 只靠提示词 / 应用描述 | 要求管理员写全描述，提示词偏向 kb_qa | 零成本 | 依赖人工；描述永远写不全（q39 在窄描述下仍误判） |
| B. 提高 out_of_scope 置信度门槛 | 低于门槛回落 kb_qa | 简单 | DeepSeek 对 q26 给出高置信，门槛挡不住；同时让真超范围也去检索生成 |
| **C. 证据复核（采纳）** | LLM 判 out_of_scope 后仍检索 + 重排，最高重排分 ≥ `out_of_scope_override_score`（默认 0.8）则改判 kb_qa 继续 judge / generate，否则维持超范围话术 | 以知识库证据为准，不依赖描述；只在 LLM 判超范围时多一次重排，成本低；无历史时复用并行检索结果，几乎不加延迟 | 超范围问题多一次检索 + 重排（约 0.001 元 / 次）；需要重排开启 |
| D. 永远检索，把检索分数喂给分类 LLM | 分类前先检索 | 信息最全 | 失去并行，首 token 延迟增加；提示词变长，每轮成本上升 |

业界做法：Rasa / Dialogflow 一类 NLU 把"fallback / out-of-scope"作为低优先级意图，并建议在 RAG 场景用检索置信度复核（"retrieval-augmented intent verification"）；搜索类客服（如 Intercom Fin、Zendesk AI）同样以"知识库是否有强匹配"作为是否回答的最终依据。C 与项目已有 judge 机制（重排分阈值 + 灰区）一致。

**决定：采纳 C。** 规则：
- 只复核 LLM 给出的 `out_of_scope`；规则层命中（敏感词 / 转人工 / 寒暄）不复核；chitchat / clarify / human / action 不复核（这些分支不会造成静默漏答或已有转人工兜底）。
- 需要 `intent.out_of_scope_check=true`（默认）且 `enable_rerank=true`；关闭重排时没有可比的分数，直接维持超范围。
- 改判后 `intent_source=fallback`、`fallback_reason=kb_evidence`，trace `intent.scope_check` 记录 `top_score / threshold / override`。
- 复核任何失败（检索 / 重排异常）维持超范围话术：兜底只会更好，不会更坏。

### 阈值评测
意图评测（M1 测试报告 §12）中 LLM 判 out_of_scope 的 10 条：9 条真超范围最高重排分 0.07–0.30，误判的 q26 为 0.98。0.5–0.95 之间任何阈值结果相同（找回 1 条、误改判 0 条）。取 **0.8**：与 `judge_gray_upper`（0.8，"高于即直接回答"）一致——改判后的问题本就会被 judge 直接放行，语义统一；两侧余量都大。

### 与验收"超范围不检索"的关系
默认配置下超范围问题会**检索与重排，但不生成、不引用**；`out_of_scope_check=false` 时严格不检索（有单测）。开发计划验收按此解释。

## 3. 其他 M2.4 取舍
- **寒暄规则匹配**：归一化（NFKC、小写、只保留字母数字）后完全匹配，且长度 ≤ 8；另试一次去掉句末语气词（呀啊啦哈哦嘛呢吧…）的形式，"你好呀""谢谢啦"命中。混合句（"你好，请问…"）超长或不完全匹配，交给 LLM。
- **内置寒暄词扩充**：评测中"早上好"走 LLM 分类时网络超时，回落 kb_qa 后被拒答；时段问候是可确定拦截的短句，加入内置 greeting（早上好、上午好、下午好、晚上好、早安），"晚安"入 bye。默认 `chitchat_keywords` 为内置表全集（意图识别 §7"见 §5.1 内置词表"）。
- **AC 自动机**：纯 Python 实现，按归一化后的词表元组 `lru_cache`，等价于按 `(app_id, config_version)` 缓存（配置不变词表就不变）。
- **无历史并行模式**：分类与检索（原问题）并行；kb_qa 直接复用检索结果并以原问题作为检索 query（无历史时改写无意义）；out_of_scope 且复核开启时保留给 scope_check；其他意图取消检索任务，trace `retrieval_cancelled=true`。
- **LLM 寒暄**：规则未命中、LLM 判 chitchat 时流式生成短回复（≤ 60 字，temperature 0.7，max_tokens 100，不开思考），提示词禁止给出业务事实；失败回落模板并记 `chitchat_llm_failed`。
- **连续拒答**：`next_refusal_streak` 纯函数（kb_qa 拒答 +1、回答清零、转人工清零、其他意图与中断 / 错误不变），由 M2.6 `chat.service` 落库时调用。
- **敏感词**：命中走 `blocked_reply`（`sensitive_reply` 话术，`answer_type=refused`，`decision_reason=sensitive_keyword`），不调 LLM。

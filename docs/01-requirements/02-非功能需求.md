# 非功能需求

## 1. 性能
| 指标 | 目标（v1） | 说明 |
|---|---|---|
| 首 token 延迟（SSE） | P50 ≤ 2.5s，P95 ≤ 5s | 含改写、检索、重排序；主要受云模型影响 |
| 完整回答（阻塞） | P95 ≤ 12s | 回答约 300 字 |
| 检索阶段 | P95 ≤ 800ms | 向量 + 关键词 + 重排序 |
| 并发对话 | 20 并发持续 10 分钟，错误率 < 1% | 单 API 实例 |
| 管理接口 | P95 ≤ 300ms | 列表类分页接口 |
| 入库速度 | 100 页 PDF ≤ 3 分钟 | 受向量化接口限流影响 |
| 规模 | 单应用 ≤ 20 万切块；全平台 ≤ 200 万切块 | 超出需评估 Qdrant 内存 |

## 2. 可用性与可靠性
- 内网服务目标可用性 99.5%（工作时间）。
- 云模型调用：超时 + 指数退避重试 2 次；连续失败触发熔断 30s，返回 `503 UPSTREAM_UNAVAILABLE`。
- 后台任务至少一次投递（`acks_late`），任务必须幂等。
- 依赖故障时：Qdrant 不可用 → 仅关键词检索（`degraded` 含 `vector_failed`）；重排序不可用 → 按 RRF 顺序取前 `rerank_top_n`，可答性改由 LLM 判断（`degraded` 含 `rerank_failed`），LLM 判断也失败则拒答；LLM 不可用 → 返回错误（assistant 消息记 `answer_type=error`），不编造。规则与 [RAG 流程设计 §4](../02-architecture/03-RAG流程设计.md) 一致。
- 数据：PG 每日全量备份保留 14 天；Qdrant 每日快照保留 7 天（可由 PG 重建）。RPO 24h，RTO 4h。

## 3. 安全
- 所有密钥只在环境变量；仓库公开，CI 中 gitleaks 扫描。
- API Key 用 HMAC-SHA256(pepper) 存储；密码 argon2id。
- 应用间数据隔离：所有查询强制 `app_id` 过滤，Qdrant 检索强制 `app_id` filter。
- 上传：类型白名单（魔数校验）、大小限制、文件名清洗、解析超时。
- 审计所有写操作。详见安全设计。

## 4. 准确率（以每个应用的评测集为准，≥ 50 题）
| 指标 | 定义 | v1 目标 |
|---|---|---|
| 检索命中率 Recall@5 | 期望文档出现在重排后前 5 | ≥ 90% |
| 引用命中率 | 回答引用中包含期望文档 | ≥ 85% |
| 答案正确率 | LLM 评判（参考期望答案）为正确 | ≥ 80% |
| 忠实度 | 回答内容均可在引用中找到依据 | ≥ 90% |
| 拒答准确率 | 应拒答的题被拒答/转人工 | ≥ 90% |
| 误拒率 | 可答题被拒答 | ≤ 10% |

## 5. 可维护性
- 测试覆盖率：核心模块（rag、memory、ingest、chat、auth）≥ 80%。
- 模块依赖方向由 import-linter 在 CI 中校验（见模块划分）。
- 所有配置项有默认值和文档；改模型只改配置。
- 日志为 JSON，每条带 `request_id`、`app_id`。

## 6. 兼容性
- 浏览器：Chrome / Edge 最新两个版本。
- 开发：Windows 11 + Python 3.12；运行：Linux 容器。

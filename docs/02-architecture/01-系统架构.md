## 2. 组件职责
| 组件 | 职责 |
|---|---|
| aics-api | HTTP 接口（开放 + 管理）、鉴权、限流、RAG 在线问答（流式） |
| aics-worker | 消费 Celery 队列：`ingest`（入库、替换、重建、重新分词）、`context`（会话压缩；出站 Webhook 投递 M3.5；消息向量化 M5.4 视结论）、`eval`（评测运行）、`maintenance`（清理、对账、统计）。生产环境 `context` 队列由独立 worker 进程消费 |
| aics-beat | Celery 定时任务（投递到 `maintenance` 队列）：空闲会话扫描 `idle_sweep`（每 30 秒：关闭前提醒、空闲关闭 ✅ M2.7；转人工排队超时、接入后无消息超时 M3.4）、删除兜底清理 `sweep_knowledge`（每小时 ✅）、`reconcile` 对账（每日 03:30 ✅）、Webhook 重试扫描 `webhook_retry_sweep`（每 10 秒，M3.5）、Key 使用时间落库 `flush_key_usage`（每分钟，M3.1）、`aggregate_daily_stats` 每日统计（每小时刷新当天，00:30 定稿前一天，M4.6）、保留期清理 `purge_expired`（每日 04:00，M6.1）（与 worker 同镜像） |
| PostgreSQL | 业务数据、切块正文、全文检索（tsvector） |
| Qdrant | 切块向量 |
| Redis | 限流计数与配额、Key 校验结果缓存（✅）、压缩锁（✅）、Celery 结果、幂等键（M3.2）、Key 使用时间（M3.1）、会话事件通知 pub/sub `aics:conv:{id}`（M3.5，事件本身存 PG `conversation_events`，ADR-0016）、refresh token 白名单（M4.1） |
| RabbitMQ | Celery 任务队列 |

## 3. 关键数据流
**入库**：上传 → API 保存文件、写 `documents(queued)` → 投递 `ingest_document` → Worker 解析、切块、分词、向量化 → 写新构建号的 `chunks` 与 Qdrant → 事务切换生效版本 → `done`（见[文档处理流水线](04-文档处理流水线.md)）。

**问答**（`chat.service.handle_turn`）：请求 → 鉴权/限流 → 加载应用配置（缓存）→ 校验会话（状态、空闲过期）→ **落库 user 消息** → LangGraph 流程（经 `MemoryPort` 组装历史）→ SSE 推送 → **落库 assistant 消息**并更新会话（`refusal_streak`、`handoff`、计数）→ 按需投递压缩（队列 `context`）。

## 4. 请求链路中的横切关注点
- `request_id` 中间件（读取或生成 `X-Request-ID`，写入日志与响应头）。
- 统一异常处理 → 统一错误体。
- 鉴权依赖：`require_api_key(scope)`（API Key scope，见[安全设计 §2.1](../08-security/01-安全设计.md)）、`require_perm(permission, app_id)`（后台 RBAC 权限）。
- 指标：请求耗时直方图、LLM token 计数、各 RAG 节点耗时。

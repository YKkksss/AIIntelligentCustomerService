# ADR-0006 对话上下文分层管理
- 状态：已接受（2026-10-14）；模块归属、OpenAI 兼容历史规则与 `history_turns` 处理被 [ADR-0008](0008-记忆模块与对话职责划分.md) 取代（`history_turns` 已移除）；第 4 条中“关键事实槽作为 M5 可选能力”被 [ADR-0014](0014-对话记忆-关键事实默认开启与版本化.md) 修订：关键事实 M2 起默认开启并版本化，会话内回查仍为 M5
- 背景：`condense` 只取最近 `history_turns`=6 轮，长对话中早期的订单号、型号等细节对模型不可见；按轮数截断无法控制 token；OpenAI 兼容接口无状态（ADR-0005）。
- 决策：
  1. 原文全量保存在 `messages`，压缩只影响送给模型的输入。
  2. 新增 `load_context` 节点，按 `history_token_budget` 依次装入关键事实 → 滚动摘要 → 近期原文（新→旧），至少保留 `keep_recent_turns` 轮。
  3. 未被摘要覆盖的原文超过 `compact_trigger_tokens` 时，Celery 任务 `compact_conversation` 异步增量生成结构化摘要（Redis 锁 + 版本乐观锁），失败不影响对话。
  4. 关键事实槽（`conversation_facts`）与会话内按需回查（Qdrant `aics_messages__*` + PG 全文检索）作为 M5 可选能力，由评测数据决定是否默认开启。
  5. 历史只用于理解意图，回答事实仍只来自知识库并带引用；跨会话长期记忆 v1 不做。
  6. OpenAI 兼容接口按同一预算裁剪，超出时请求内临时摘要，不落库。
- 后果：每次压缩多 1–2 次 LLM 调用；`messages`、`conversations` 加列，新增一张表和一个 Qdrant 集合；需要长对话评测用例守住质量；`history_turns` 进入兼容保留状态。详见[对话上下文管理](../07-对话上下文管理.md)。

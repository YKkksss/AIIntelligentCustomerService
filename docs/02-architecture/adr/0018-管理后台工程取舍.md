# ADR-0018 管理后台的工程取舍：后端手写管理接口、前端自建骨架

- 状态：已接受（2026-10-19；M4.1 起落地）；修订 [管理后台设计](../../05-frontend/01-管理后台设计.md) §1 与 [后续里程碑详细计划 M4](../../00-planning/06-后续里程碑详细计划.md)
- 背景：M4 要在浏览器里完成全部运营工作（[管理后台设计](../../05-frontend/01-管理后台设计.md) §3 约 20 个页面）。开工前有两条省事的路：
  1. 引入通用后台框架 / 无头 CMS（Django admin、Strapi、Directus、Payload、Refine）；
  2. 整仓 fork 一个成熟的 Vue3 admin 模板（vue-vben-admin、Soybean Admin、vue-pure-admin 一类），把业务页填进去。
  现状：`frontend/` 只有 M0 骨架（5 个源文件：`main.ts`、`api/http.ts`、`stores/auth.ts`、`router/index.ts`、两个占位页面），依赖已是 **Vue 3.5 / Element Plus 2.14 / Vite 8 / TypeScript 6 / vue-router 5 / Pinia 4**；后端已有 22 个开放端点与成套 service / repository，管理接口清单写在 [管理接口参考](../../04-api/03-管理接口参考.md)。
- 决策：
  1. **后端管理接口手写**，按模块放在 `modules/<m>/admin_router.py`，统一前缀 `/api/v1/admin`，JWT 鉴权（M4.1），复用既有 `service` / `repository`，**不引入任何 BaaS / CRUD 框架**。理由：本项目的关键约束全在业务层——`app_id` 租户隔离（`AppScopedRepository`）、`config_version` 合并与 80% 窗口校验、事件 outbox 与 `seq`、转人工状态机、审计 diff、`channel=debug` 不计统计。通用后台只能"读表改表"，这些语义一个都表达不了，硬接等于把校验与事件绕过去。且引入第二个运行时（Node/PHP/Docker 服务）与现有单进程 FastAPI + Celery 的部署方式冲突。
  2. **前端不整仓 fork 模板，自建骨架**，只参考两类现成实现：布局与动态菜单（含权限指令）、axios 刷新队列。理由：本仓库依赖版本（Vite 8 / TS 6 / vue-router 5 / Pinia 4）比主流模板的锁版本新，fork 进来第一件事就是降级；模板自带 mock 层、i18n、主题系统与演示页，与 `ui/aics-admin.pen` 的设计稿互相打架；依赖体积与后续升级成本都高于自己写布局（约 2 人日）。
  3. **类型由契约生成**：`npm run gen:api` 用 `openapi-typescript` 从后端 `/openapi.json` 生成 `src/api/schema.d.ts`（生成文件加入 ESLint / Prettier 忽略），前端不手写接口类型。
  4. 组件库唯一 **Element Plus**，图表 `echarts`，SSE 用 `@microsoft/fetch-event-source`（[管理后台设计](../../05-frontend/01-管理后台设计.md) §1 已定）；不因为引入某个模板而换组件库。
  5. 前端测试：Vitest 覆盖逻辑层（store、拦截器、`v-perm`、路由守卫，门槛 80%，`.vue` 不计入）+ 里程碑 Playwright 冒烟（设计讨论 0009 D13）。
- 后果：
  - M4.1 先做后端鉴权面（迁移、`modules.auth`、`core.security.require_perm`、`core.audit`、`bootstrap-admin`），再做前端骨架（布局、登录、拦截器、`v-perm`、类型生成、Vitest 基座），最后按价值排页面：会话日志与调试对话优先（它们验证 trace / 事件链路），配置表单次之，仪表盘与评测在 M4.6 / M5。
  - 管理接口与开放接口**绝不共用鉴权**：开放接口走 API Key + scope，管理接口走 JWT + 点分权限名（[安全设计 §2.1](../../08-security/01-安全设计.md)），两套命名不得混用。
  - 代价与风险：页面样式要自己对齐设计稿；前端工作量集中在 6 个重交互页面（调试对话、知识库、文档详情、会话日志、配置表单、评测结果），模板本来也帮不上这些。

# ADR-0008 记忆模块与 chat / rag / memory 职责划分
- 状态：已接受（2026-10-15）；部分取代 ADR-0005（会话关联）、ADR-0006（模块归属、`history_turns`）；第 7 条被 ADR-0010（空闲关闭）与 ADR-0011（转人工）取代
- 背景：v0.1 设计中 `rag` 的 `load_context` 直接调用 repository 读事实与会话，rag 既算回答又隐含落库；消息落库时机（"异步不阻塞"）、`refusal_streak` 与 `handoff` 由谁更新、压缩由谁触发均未定义；调试、评测、OpenAI 兼容接口各自可能拼装流程；`history_turns` 一边"已废弃"一边仍被 OpenAI 兼容接口使用；压缩队列 `context` 未出现在队列清单中。
- 决策：
  1. 新增领域库 `aics.memory`（`load_context`、`compactor`、`facts`、`recall`），拥有会话上下文相关的读写（`conversations.summary*`、`conversation_facts`、消息向量），对 `messages` 只读；内部通过 `ConversationStore` 接口访问数据。
  2. `aics.rag` 只依赖 `rag.ports`（`MemoryPort`、`ChunkSearch`）、providers、vectorstore、core；不 import `db` 与业务模块。rag 图只返回 `RagResult`，不写库。
  3. `chat.service.handle_turn()` 是唯一的对话编排入口：校验会话 → 生成前落 user 消息 → 调用 rag → 落 assistant 消息（中断带 `interrupted=true`，异常写 `answer_type=error`）→ 更新 `refusal_streak` / `handoff` / 计数 → 逐轮槽位写事实 → 压缩触发。调试对话、评测、OpenAI 兼容接口全部复用。
  4. `AppRagConfig` 唯一定义在 `aics/rag/config.py`；`apps` 模块只负责持久化与缓存。
  5. Celery 增加队列 `context`（`compact_conversation`、`embed_message`），独立 worker 进程消费；任务只调用 service。
  6. 移除 `history_turns`；历史长度只由 `history_token_budget` + `keep_recent_turns` 决定。OpenAI 兼容接口：带 `X-AICS-Conversation-Id` 时使用服务端会话历史；不带时无状态，使用请求 `messages` 并按同一预算裁剪，每次请求新建一个 `channel=openai` 会话仅用于日志与反馈。
  7. 会话增加 `status`（active/closed），空闲超过 `AICS_CONVERSATION_IDLE_TTL_HOURS`（默认 24）关闭，向已关闭会话发消息返回 `409 CONVERSATION_CLOSED`；转人工后会话保持 active，后续消息照常由 AI 处理。
- 后果：模块数增加一个，依赖方向可由 import-linter 校验；rag 可在无数据库的单测中运行；落库顺序确定，断线与异常都有消息记录；接入方需处理 `CONVERSATION_CLOSED`。详见[模块划分](../02-模块划分.md)、[对话上下文管理](../07-对话上下文管理.md)。

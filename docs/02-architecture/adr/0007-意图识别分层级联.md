# ADR-0007 意图识别分层级联
- 状态：已接受（2026-10-15）
- 背景：`guard` 只处理转人工关键词与连续拒答，"你好""谢谢"等寒暄也进入检索并被拒答，计入 `refusal_streak`，连续两次即误转人工；超出范围、业务办理、含糊问题都没有专门去向。项目尚无标注数据，且多应用平台下每个应用的业务范围不同。
- 决策：
  1. 采用三层级联：规则（guard）→ LLM 合并分类（condense_classify）→ 向量快速通道（M5 以后视评测数据决定），不训练小分类模型。
  2. 规则层（~1ms）依次判断敏感词、转人工关键词（沿用 `handoff_config.keywords`）、连续拒答、寒暄短句完全匹配；只拦确定的输入，结果不可被 LLM 或用户输入覆盖。
  3. condense 改为一次调用输出 `{rewritten_query, intent, confidence, need_clarify, clarify_question, slots}`，Pydantic 校验；意图 6 类：`kb_qa`、`chitchat`、`human`、`out_of_scope`、`action`、`clarify`。
  4. 解析失败、超时、`confidence < min_confidence`(0.6)、意图未启用等一律回落 `kb_qa`。
  5. 无历史时分类与检索并行，非 kb_qa 时丢弃检索结果，关键路径不增加延迟。
  6. 非 kb_qa 分支不检索、不带引用、不计入 `refusal_streak`；`action` 在 v1 转人工，v1.1 接工具调用与槽位追问。
  7. 接口 `answer_type` 取值不变，新增 `intent` 字段；配置放在 `rag_config.intent`。
- 后果：首句多一次小 LLM 调用、非 kb_qa 首句多一次检索；`messages` 加 4 列、评测表加列，M5+ 可能新增 `intent_examples` 表与 `aics_intents` 集合；需要意图评测用例与"知识问答漏答率"守住不漏答。详见[意图识别](../08-意图识别.md)。

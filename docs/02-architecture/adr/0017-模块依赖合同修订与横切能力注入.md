# ADR-0017 模块依赖合同修订与横切能力（权限、审计）注入
- 状态：已接受（2026-10-17；合同修改落地 M3.4，端口落地 M4.1）；修订 [模块划分 §3](../02-模块划分.md)
- 背景：`backend/pyproject.toml` 中 L3 模块之间的 forbidden 合同未设 `allow_indirect_imports`，import-linter 默认连**间接**链路也检查。`handoff → chat → apps` 与 `eval → chat → apps / webhooks` 都是设计允许的直接依赖叠加出的间接依赖，按现有合同会被判违规；`handoff` 还需要读 `handoff_config`（属于 apps），而合同禁止 `handoff → apps`。另外，后台的权限校验（auth）与审计（audit）是每个模块都要用的横切能力，而独立性合同禁止业务模块 import auth / audit。讨论见[设计讨论 0009](../../09-design-discussions/0009-文档审计与M3至v1.0规划取舍（交接）.md)。
- 决策：
  1. "X 只可依赖 …"类 forbidden 合同（chat、handoff、eval、feedback）加 `allow_indirect_imports = true`，只约束直接 import；分层合同与 `rag` / `memory` / `ingest` / `core` 的 forbidden 合同不变（仍检查间接）。
  2. `handoff` 的允许列表增加 `apps`：handoff 只可依赖 `chat`、`webhooks`、`apps`。
  3. 横切能力用 core 端口：
     - `core.security.require_perm(permission)`：FastAPI 依赖，从 `app.state.authorizer`（Protocol `Authorizer`，`modules.auth` 实现）取得当前用户与其在路径 `app_id` 上的权限；
     - `core.audit.AuditSink`（Protocol）：`write(session, entry)` 在调用方事务内写 `audit_logs`，`modules.audit` 实现，`aics.main` 注入到 `app.state.audit`；业务 service 通过参数拿到 sink，不 import audit。
  4. `stats` 的聚合查询可以只读地直接使用 `aics.db.models`（`messages`、`conversations`、`feedback` 等），不 import 其他模块。这是唯一的"跨模块读表"例外，写入仍只能经所属模块的 service。
- 后果：
  - M3.4 的第一个提交先改合同，`uv run lint-imports` 必须通过，再写 handoff 代码。
  - 模块独立性合同（auth / apikeys / audit / stats / webhooks / knowledge / apps 互相独立）保持不变。
  - 合同变更同步写入 `pyproject.toml` 中合同上方的注释与[模块划分 §3](../02-模块划分.md)。

# ADR-0019 AI 交互页面的组件选型：ai-elements-vue（copy-in）+ Tailwind utilities-only

- 状态：已接受（2026-10-20；M4.4 起落地）；修订 [ADR-0018](0018-管理后台工程取舍.md) §4（"组件库唯一 Element Plus"）——**仅调试对话页**引入第二套样式链，其余页面不变
- 背景：M4.4 要做一个"通用后台模板写不出来"的页面——聊天区（流式气泡、Markdown、停止/重新开始）+ 检索面板（融合与重排分数、意图、上下文、耗时、原始 trace）。这类页面在 React 生态有官方成品 [Ant Design X](https://x.ant.design/components/introduce-cn/)（Bubble / Sender / Conversations / ThoughtChain），但**官方只支持 React**；我们的管理后台是 Vue 3.5 + Element Plus（ADR-0018）。开工前的候选：
  1. **官方 Ant Design X 做单页 React 孤岛**（`react` + `react-dom` + `@ant-design/x`，Vite 多框架共存）：组件最全，但引入第二个 UI 运行时与第二套设计体系，ADR 要改写、包体与维护成本都上去；
  2. **Vue 3 的社区移植**（`ant-design-x-vue-next` 一类）：栈一致，但移植进度与主题适配要现场赌；
  3. **照规范自研薄组件**：零新依赖，但流式气泡、思维链折叠、Markdown 增量渲染这些都要自己写；
  4. **`ai-elements-vue`**：把组件源码复制进仓库的 shadcn-vue 注册表（MIT，`node>=20.19`），组件清单与 Ant Design X 基本一一对应（`conversation` / `message` / `prompt-input` / `reasoning` / `sources` / `inline-citation` / `tool` / `chain-of-thought` / `loader`），栈仍是 Vue。
- 决策：
  1. **采用 `ai-elements-vue`**（方案 4），只按需安装 `conversation`、`message`、`prompt-input`、`reasoning`、`sources`、`loader`，源码落在 `frontend/src/components/ai-elements/`。理由：与 Vue 栈一致、组件覆盖 M4.4 需要的全部形态、源码归仓库所有（可按 `ui/aics-admin.pen` 改样式），且不像 React 孤岛那样把页面锁进第二个运行时。**放弃方案 1**（React 孤岛）：它换来的是"官方组件"，代价是双运行时 + 两套设计体系，而 ai-elements-vue 的组件面已经够用。
  2. **Tailwind 只引 utilities**：v4 下 `@import "tailwindcss/theme.css"` + `@import "tailwindcss/utilities.css"`，**不引 preflight**（preflight 会重置 Element Plus 的按钮、输入框、表格样式）；容器包一层 `.aics-ai` 作用域。shadcn 的语义变量（`--primary`、`--border`、`--muted-foreground` 等）映射到设计 token（`--aics-primary=#1677FF`、`--aics-sider=#001529`…），与 `frontend/src/styles/theme.css` 同源。
  3. **组件只做展示层**：数据来自 `/api/v1/admin/apps/{app_id}/debug/chat` 的 SSE（事件名与开放接口一致：`start` / `trace` / `citations` / `delta` / `end` / `error`），前端自写 `api/debug.ts` 用 `fetch` + `ReadableStream` 解析（`EventSource` 带不了 `Authorization` 头）。**不引入 Vercel AI SDK 的运行时**（只用到它的类型）。
  4. **样式契约**：Element Plus 仍是通用组件库（表单、表格、弹窗、分页）；ai-elements 组件只出现在调试对话页。新增页面若要用它们，先在 ADR 里补一句理由。
  5. **测试契约**：复制进来的组件不计入覆盖率（与 `schema.d.ts` 同等对待，加入 vitest coverage exclude）；页面逻辑（SSE 状态机、trace → 面板数据映射、临时参数 diff）必须有用例，门槛仍是语句 80%。
- 后果：
  - 正面：栈一致（无 React 运行时）、组件齐全（气泡 / 流式 Markdown / 思维链 / 来源 / 输入框都现成）、源码可改（对齐设计稿与 `--aics-*` token 不用等上游）。
  - 负面：仓库里出现**第二条样式链**（Tailwind utilities），`components.json` 与 `frontend/src/components/ai-elements/` 成为新的目录约定；升级时要重新执行 `npx ai-elements-vue add …` 覆盖，人工改动需要合并。
  - 风险与缓解：① Tailwind 与 Element Plus 互相干扰 → 只引 utilities + `.aics-ai` 作用域，构建后用截图对比既有四个页面；② 组件默认 shadcn 中性色与设计稿不一致 → 变量映射，不改组件源码；③ `message` 组件会带 `katex` / mermaid 等可选依赖 → 只装需要的子组件，先不启用 mermaid；④ 组件是复制件，升级不自动 → 在 `frontend/src/components/ai-elements/README.md` 记录版本与安装命令。

# ADR-0014 对话记忆：关键事实默认开启、版本化与标识符护栏
- 状态：已接受（2026-10-16）；修订 [ADR-0006](0006-对话上下文分层管理.md) 第 4 条（关键事实不再是 M5 可选能力）
- 背景：设计讨论 [0002](../../09-design-discussions/0002-对话记忆方案（参考业界分层记忆）.md) 对照业界分层记忆（Mem0、Zep、Letta、LangGraph、ChatGPT 记忆）评审了 v0.2 方案：客服场景最常见的失败是忘记 / 混淆用户刚提供的订单号、手机号；原方案事实只做覆盖式 upsert 且推迟到 M5。
- 决策：
  1. `conversation_facts` 从 M2 起启用，`enable_facts` 默认 `true`；事实（按重要度排序、上限 300 token）每轮固定注入 `load_context`。
  2. 事实带 `category`、`importance`、`source`、`version`、时间戳；更新与撤回写追加式 `conversation_fact_history`，不覆盖丢失旧值；对账操作 ADD / UPDATE / NOOP / RETRACT。
  3. postprocess 增加标识符一致性规则检查（订单号 / 手机号），不一致记 `identifier_mismatch`（只检测与告警，不改写已流式输出的文本）。
  4. 会话内回查（M5）用向量 + 关键词 RRF 再叠加时近度衰减排序。
  5. 不做：跨会话长期记忆（v2，需接入方传 user_id）、Agent 工具自管理记忆、知识图谱、衰减与冷热分层。
- 后果：M2.1 多两张表；M2.5 工作量增加（抽取对账、护栏、预算评测）；每轮事实区增加 < 300 token；记忆质量有三项可回归的指标。详见[对话上下文管理](../07-对话上下文管理.md)。

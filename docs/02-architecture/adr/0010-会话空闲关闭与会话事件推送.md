# ADR-0010 会话空闲关闭与会话事件推送
- 状态：已接受（2026-10-15）；取代 ADR-0008 第 7 条中"固定 24 小时关闭、向已关闭会话发消息返回 409"的部分
- 背景：客服会话通常几分钟内结束，固定 24 小时过长，且不同应用需求不同；关闭前应提醒用户；返回 409 迫使每个接入方写重试逻辑。
- 决策：
  1. 按应用配置 `session_config.idle_close_minutes`（默认 10）、`idle_notice_before_minutes`（默认 1，0 = 不提醒，必须小于关闭分钟数）、`idle_close_notice`（默认"如果没有其他问题，当前服务就结束咯~"）；为空的键取平台默认（`system_settings`，后台系统设置可改）。
  2. 唯一机制：beat 每 30 秒投递 `idle_sweep`（队列 `maintenance`），用条件更新先提醒、再关闭；不为每条消息排程延迟任务。
  3. 提醒写为 `role=system, kind=idle_notice` 消息，经会话事件流 SSE、出站 Webhook、消息列表三条通道送达。
  4. 向已关闭会话发消息：自动新建会话（不继承历史），响应返回新 `conversation_id` 与 `previous_conversation_id`。
- 后果：消息表增加 `system` 角色与 `kind` 列；新增会话事件流接口与 Redis pub/sub；提醒/关闭时间误差 ≤ 30 秒。详见[会话生命周期与转人工](../09-会话生命周期与转人工.md)。

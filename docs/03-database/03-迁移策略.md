# 数据库迁移策略（Alembic）

- 位置：`backend/migrations/`，`env.py` 使用异步引擎，`target_metadata = Base.metadata`。
- 生成：`uv run alembic revision --autogenerate -m "add feedback table"`，**必须人工检查**生成的脚本（autogenerate 不识别生成列、部分索引需手写）。
- 命名：`YYYYMMDD_HHMM_<描述>.py`（`file_template` 配置）。
- 每个迁移都写 `downgrade()`；破坏性变更分两步：先加新列并双写 → 发布 → 再删旧列。
- 种子数据（roles）放在迁移里；初始管理员由启动命令 `aics-cli bootstrap-admin` 创建，不放迁移（roles 表与该命令都在 M4.1 落地；截至 M2.7 只有 0001–0010 迁移，见[接手代码地图](../00-handoff/02-实现现状与代码地图.md)）。
- 执行：开发 `uv run alembic upgrade head`；生产部署脚本在启动 API 前执行，失败则中止部署。
- 发布前在测试库上 `upgrade → downgrade -1 → upgrade` 验证。
- 应用账号只拥有 `aics` 库内对象，迁移使用同一账号（库所有者）；生产环境可拆分 `aics_migrator`（DDL）与 `aics_app`（DML），v1 不强制。

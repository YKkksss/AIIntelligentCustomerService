服务器：192.168.110.86（Ubuntu 24.04，8 核，15GB 内存，**实际可用约 1.5GB**（2026-10-15 复查），无 GPU，Docker 29）。SSH 别名 `knowledgeflow-server`。

> **当前状态（2026-10-15 已完成）**：PG 16.15（容器 `db-postgres-1`）库 `aics`、`aics_test` 与角色 `aics`；RabbitMQ 4.3.5 vhost 与用户 `aics`；Redis 8.2.9 ACL 用户 `aics`（库号 5，规则见 §3）；Qdrant 共用 KnowledgeFlow 的实例（§7），AICS 不再部署自己的 Qdrant。

> 脚本：本文第 1–4、6 节的操作已写成可重复执行的 [`deploy/server/bootstrap/bootstrap.sh`](../../deploy/server/bootstrap/README.md)（子命令 `check` / `dirs` / `postgres` / `rabbitmq` / `redis-acl`，密码从环境变量或交互输入读取）；PG 部分为 `deploy/server/bootstrap/postgres.sql`。下面保留手动步骤供核对。

> **边界**：只创建属于 AICS 的库、用户、库号、vhost 和 `aics-*` 容器。不修改、不重启 KnowledgeFlow、xianyu、mysql 相关容器与共享服务的配置。所有 `<...>` 为占位符，真实密码只写进服务器与开发机的 `.env`。

## 1. 目录
```bash
sudo mkdir -p /data/aics/{storage,backups/pg,backups/qdrant,backups/storage,logs}
sudo chown -R $USER:$USER /data/aics
mkdir -p ~/aics          # 放 deploy/ 下同步过来的脚本与 compose 文件（M6 应用部署）
```

## 2. PostgreSQL（容器 db-postgres-1）
需要共享实例的管理员账号（向服务器负责人获取，记为 `<PG_ADMIN_USER>`）。
```bash
docker exec -it db-postgres-1 psql -U <PG_ADMIN_USER> -d postgres
```
```sql
CREATE ROLE aics LOGIN PASSWORD '<AICS_DB_PASSWORD>' CONNECTION LIMIT 40;
CREATE DATABASE aics OWNER aics ENCODING 'UTF8' TEMPLATE template0;
REVOKE ALL ON DATABASE aics FROM PUBLIC;
\c aics
REVOKE ALL ON SCHEMA public FROM PUBLIC;
ALTER SCHEMA public OWNER TO aics;
-- 测试库（集成测试用）
CREATE DATABASE aics_test OWNER aics ENCODING 'UTF8' TEMPLATE template0;
```
验证（开发机）：`psql "postgresql://aics:<AICS_DB_PASSWORD>@192.168.110.86:5432/aics" -c "select 1"`。
> 若实例 `pg_hba.conf` 不允许该网段的密码登录，需负责人添加 `host aics,aics_test aics 192.168.110.0/24 scram-sha-256`。

## 3. Redis
- 使用库号：5（缓存、限流、幂等），6（Celery 结果），7（测试）。所有 key 带 `aics:` 前缀。
- Redis 8.2.9 已启用 ACL，AICS 专用用户 `aics` 写在服务器 `/etc/shared-infra/redis.conf` 的 `user` 行中（由负责人维护，重启后保留）：
```
user aics on >'<AICS_REDIS_PASSWORD>' ~aics:* ~celery-task-meta-* ~chord-unlock-* &aics:* &celery-task-meta-* +@all -@admin -@dangerous
```
  - key：只允许 `aics:*`（缓存、限流、幂等、锁）、`celery-task-meta-*`（Celery 结果）、`chord-unlock-*`（Celery chord）。
  - pub/sub 频道：`aics:*`（会话事件 `aics:conv:{id}`）、`celery-task-meta-*`（Celery 结果订阅）。
  - 命令：去掉 `@admin`、`@dangerous`，因此 **`KEYS`、`FLUSHDB`、`FLUSHALL`、`INFO`、`CONFIG`、`DEBUG` 等不可用**；AICS 代码只用普通读写、`SCAN` + 前缀、`PING`（`/readyz`）、pub/sub。
- URL：`redis://aics:<AICS_REDIS_PASSWORD>@192.168.110.86:6379/5`；Celery 结果后端同一用户，库号 6（`AICS_CELERY_RESULT_BACKEND`）。库号 7 留给集成测试。

## 4. RabbitMQ
```bash
docker exec -it <rabbitmq容器名> bash
rabbitmqctl add_vhost aics
rabbitmqctl add_user aics '<AICS_MQ_PASSWORD>'
rabbitmqctl set_permissions -p aics aics ".*" ".*" ".*"
rabbitmqctl set_user_tags aics management     # 可在 15672 查看自己的 vhost
```
（RabbitMQ 4.3.5，已执行。）
验证：浏览器打开 `http://192.168.110.86:15672`，用 aics 登录只能看到 vhost `aics`。

## 5. 防火墙
只允许内网访问：
```bash
sudo ufw allow from 192.168.110.0/24 to any port 8080 proto tcp   # M6 应用上线后
```
（若服务器未启用 ufw，与负责人确认后再启用，避免影响其他服务。）

## 6. 部署前检查

```bash
free -h; df -h /data; docker ps --format '{{.Names}}\t{{.Ports}}'
ss -ltnp | grep -E ':8080\b' || echo "端口空闲"
```

## 7. Qdrant（共用 KnowledgeFlow 实例）
- 实例：KnowledgeFlow 的 `qdrant/qdrant:v1.18.2`，`http://192.168.110.86:6333`，需要 API Key（向负责人获取，填入 `AICS_QDRANT_API_KEY`）。
- 隔离：AICS 只创建、读写、删除 **`aics_` 前缀**的集合（`AICS_QDRANT_COLLECTION_PREFIX`，默认 `aics_`；集成测试用 `aics_test_`），不得列举后操作其他集合；该 API Key 对整个实例有权限，代码层只经 `aics.vectorstore` 访问，集合名由它统一生成。
- 客户端：`qdrant-client` 1.15+（与服务端 1.18 兼容）。
- 资源：不再为 AICS 单独限制 Qdrant 内存；AICS 集合使用 int8 量化与磁盘原向量（见 Qdrant 设计），上线前与 KnowledgeFlow 负责人确认容量。详见[Qdrant 部署](02-Qdrant部署.md)。

# 监控与运维手册

## 1. 监控
- 指标端点 `GET /metrics`（仅内网，Nginx 不对外暴露）：
  - `aics_http_requests_total{route,status}`、`aics_http_request_duration_seconds`
  - `aics_rag_node_duration_seconds{node}`、`aics_chat_first_token_seconds`
  - `aics_chat_answers_total{app_id,answer_type}`（拒答率、转人工率）
  - `aics_llm_tokens_total{provider,model,kind}`、`aics_provider_errors_total{provider,code}`、`aics_circuit_open{provider}`
  - `aics_celery_queue_length{queue}`、`aics_documents_failed_total`
- 若服务器已有 Prometheus/Grafana 则接入；没有则 v1 用后台仪表盘 + 日志告警，Prometheus 栈列为 v2。
- 建议告警：5 分钟 5xx 比例 > 5%；首 token P95 > 8s；熔断打开；`ingest` 队列积压 > 100 持续 10 分钟；`context` 队列积压 > 50 持续 10 分钟；`webhook_deliveries` 最终失败数（指标 `aics_webhook_failures_total{app_id}`）持续上升或 `aics_compaction_failures_total` 持续上升；`/readyz` 失败；磁盘 `/data` > 85%；Qdrant 内存 > 80%。

## 2. 日志
JSON 字段：`ts, level, event, request_id, app_id, user_id|api_key_prefix, route, status, latency_ms`。查看：`docker logs aics-api --since 10m | jq 'select(.level=="error")'`。

## 3. 日常操作
| 操作 | 命令 |
|---|---|
| 状态 | `docker compose -p aics ps`；`curl localhost:8080/readyz` |
| 重启 API | `docker compose -p aics restart aics-api` |
| 查看队列 | RabbitMQ 管理页 vhost `aics` |
| 重建应用索引 | 后台「应用 → 重建」或 `docker compose exec aics-api aics-cli reindex --app <id>` |
| 对账 | `aics-cli reconcile --app <id>` |
| 吊销 Key | 后台「API Key → 吊销」 |

## 4. 故障处理
| 现象 | 排查 | 处理 |
|---|---|---|
| 对话全部 503 UPSTREAM_UNAVAILABLE | 日志 `provider.error`；DeepSeek / 百炼状态页 | 等待恢复；必要时改 `AICS_LLM_*` 切换备用模型并重启 |
| 回答大量 refused | 仪表盘拒答率突增；检查 rerank 是否降级、Qdrant 是否可用、最近是否改了阈值 | 回退应用配置（看审计日志 diff） |
| 文档一直 queued | worker 是否运行；RabbitMQ 连接 | 重启 worker；任务幂等，可重新投递 |
| 长对话"记不住"、`history_gap` 偏高 | `aics-worker-context` 是否运行、`context` 队列积压 | 重启 aics-worker-context |
| 文档 failed | 文档详情 error | 解析问题→转换格式后重传；限流→重试 |
| `/readyz` postgres 失败 | 共享 PG 是否重启、连接数是否打满 | 联系负责人；应用会自动重连 |
| 内存不足 | `free -h`、`docker stats` | 降低 worker 并发；不要动其他项目容器 |
| 疑似 Key 泄露 | 审计日志、该 Key 用量突增 | 立即吊销并新建，通知接入方 |

## 5. 密钥轮换
| 密钥 | 步骤 |
|---|---|
| DeepSeek / 百炼 | 控制台新建 → 更新服务器 `.env` → 重启 api/worker → 验证 → 删除旧 Key |
| DB / MQ / Redis 密码 | 修改账号密码 → 更新 `.env` → 重启 |
| Qdrant API Key | 共用 KnowledgeFlow 实例，由其负责人轮换；拿到新 Key 后更新应用 `.env` 的 `AICS_QDRANT_API_KEY` → 重启 api/worker |
| JWT secret | 更新 → 重启（所有用户需重新登录） |
| API Key pepper | 一般不轮换；轮换会使所有接入方 Key 失效，需提前通知 |

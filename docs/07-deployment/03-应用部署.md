# 应用部署（M6 起）

## 1. 形态
在服务器上以容器运行（`deploy/app/docker-compose.yml`，项目名 `aics`）：
| 服务 | 镜像 | 端口 | 内存上限 |
|---|---|---|---|
| aics-api | `ghcr.io/<org>/aics-backend:<tag>` | 内部 8000 | 768MB |
| aics-worker | 同上，命令 `celery worker -Q ingest,eval,maintenance -c 2` | — | 768MB |
| aics-worker-context | 同上，命令 `celery worker -Q context -c 2`（会话压缩、消息向量化；与入库分开，避免被大文件阻塞） | — | 256MB |
| aics-beat | 同上，命令 `celery beat` | — | 128MB |
| aics-web | `ghcr.io/<org>/aics-web:<tag>`（Nginx：静态前端 + 反代 `/api`、`/v1` 到 api，关闭 SSE 缓冲） | **8080** → 80 | 64MB |

合计新增约 2.0GB（加 Qdrant 1GB），在可用内存范围内；上线前复查 `free -h`。若 8080 已被占用，改用其他端口并同步修改接入文档中的 BASE。

上传文件挂载 `/data/aics/storage:/app/storage`，日志输出到 stdout（json-file 驱动轮转）。

Nginx 关键配置：
```nginx
location ~ ^/(api|v1)/ {
  proxy_pass http://aics-api:8000;
  proxy_http_version 1.1;
  proxy_buffering off;            # SSE 必须
  proxy_read_timeout 300s;
  client_max_body_size 55m;
  proxy_set_header X-Request-ID $request_id;
  proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
}
```

## 2. 发布流程（与 Git 分支模型对应）
1. `dev` 满足发布条件 → PR 合并到 `main` → 打 tag `vX.Y.Z`（见 Git 工作流）。
2. `release.yml` 构建并推送镜像（tag 与版本号一致），创建 GitHub Release。**只有 `main` 上的 tag 才会部署到服务器**；`dev` 只在开发机运行。
3. 服务器执行：
```bash
cd ~/aics/app
export AICS_VERSION=v1.0.0
./deploy.sh $AICS_VERSION
```
`deploy.sh` 步骤：拉取镜像 → 备份数据库（见备份）→ `docker compose run --rm aics-api alembic upgrade head` → `docker compose up -d` → 轮询 `/readyz` 60s → 失败自动回滚到上一版本镜像（迁移需可向后兼容）。
4. 冒烟：用测试 Key 调一次 `/api/v1/apps/{app_id}/chat`。
5. 在 Release 记录中写部署时间与结果。

镜像仓库若为公开（GHCR 公开包），镜像内不得包含 `.env` 或任何密钥；运行时通过服务器上的 `~/aics/app/.env`（chmod 600）注入。

## 3. 离线镜像（可选）
需要在项目目录保留镜像副本时：`docker save ghcr.io/<org>/aics-backend:v1.0.0 -o docker/images/aics-backend_v1.0.0.tar`（已 gitignore，不入库）；导入用 `docker load -i`。

## 4. 回滚
`./deploy.sh v0.9.2`；若新版本包含不可逆迁移，按备份恢复（见备份与恢复）。

# 备份与恢复

| 对象 | 方式 | 频率 | 保留 | 位置 |
|---|---|---|---|---|
| PostgreSQL `aics` | `pg_dump -Fc` | 每日 02:30 + 每次部署前 | 14 天 | `/data/aics/backups/pg/` |
| Qdrant（只含 `aics_` 集合） | 快照 API（逐集合创建并下载） | 每日 03:00 | 7 天 | `/data/aics/backups/qdrant/` |
| 上传文件 | `rsync` / tar 增量 | 每日 03:30 | 14 天 | `/data/aics/backups/storage/` |
| 服务器 `.env` | 手工加密保存（密码管理器） | 变更时 | — | 不放仓库 |

建议每周将 `/data/aics/backups` 同步到另一台机器（RPO 24h）。

## 脚本（`deploy/scripts/backup.sh` 要点）
```bash
set -euo pipefail
TS=$(date +%Y%m%d_%H%M)
docker exec db-postgres-1 pg_dump -U aics -d aics -Fc > /data/aics/backups/pg/aics_$TS.dump
# 共用 KnowledgeFlow 的 Qdrant：只对 aics_ 前缀集合做快照，并下载到 AICS 自己的目录
for c in $(curl -sf -H "api-key: $QDRANT_API_KEY" http://127.0.0.1:6333/collections | jq -r '.result.collections[].name | select(startswith("aics_"))'); do
  snap=$(curl -sf -X POST -H "api-key: $QDRANT_API_KEY" "http://127.0.0.1:6333/collections/$c/snapshots" | jq -r .result.name)
  curl -sf -H "api-key: $QDRANT_API_KEY" -o "/data/aics/backups/qdrant/${c}_$TS.snapshot" "http://127.0.0.1:6333/collections/$c/snapshots/$snap"
  curl -sf -X DELETE -H "api-key: $QDRANT_API_KEY" "http://127.0.0.1:6333/collections/$c/snapshots/$snap" >/dev/null
done
tar -czf /data/aics/backups/storage/storage_$TS.tar.gz -C /data/aics storage
find /data/aics/backups/pg -name '*.dump' -mtime +14 -delete
find /data/aics/backups/qdrant -name '*.snapshot' -mtime +7 -delete
```
crontab：`30 2 * * * /home/<user>/aics/scripts/backup.sh >> /data/aics/logs/backup.log 2>&1`

## 恢复
- PG：`docker exec -i db-postgres-1 pg_restore -U aics -d aics --clean --if-exists < aics_xxx.dump`（先停 api/worker）。
- Qdrant：快照上传恢复 `PUT /collections/{name}/snapshots/upload`；**或直接从 PG 重建**：`aics-cli reindex --all`（不需要重新解析，只重新向量化，耗费 embedding 费用）。
- 文件：解压回 `/data/aics/storage`。

## 演练
上线前及每季度：在 `aics_test` 库恢复最近一次备份，校验表行数与抽样文档可检索，记录耗时（目标 RTO 4h）。

# 开发计划

> 估时按"一名开发 + AI 助手"计，单位为人日（d）。每个阶段结束都必须**能运行、能演示**，并在 `dev` 上通过 CI。
> 分支模型：所有开发在 `dev` 或 `feature/*`（从 `dev` 拉出）上进行；每个里程碑达成后，`dev` 合并到 `main` 并打 tag（`vX.Y.Z`）。`main` 只保存已发布版本。详见 [Git 工作流](../06-development/04-Git工作流.md)。

## 里程碑总览
| 里程碑 | 版本 tag | 内容 | 估时 |
|---|---|---|---|
| M0 基础设施 | v0.1.0 | 仓库、工程骨架、服务器服务就绪 | 3d |
| M1 知识库入库 | v0.2.0 | 上传→解析→切块→向量化→入库 | 6d |
| M2 问答核心 | v0.3.0 | LangGraph RAG + 对话接口（阻塞/SSE） | 7d |
| M3 开放接口 | v0.4.0 | API Key、限流、OpenAI 兼容、知识库接口 | 4d |
| M4 管理后台 | v0.5.0 | 登录、应用、知识库、调试对话、Key、日志 | 8d |
| M5 评测与质量 | v0.6.0 | 评测集/运行、反馈、调参对比 | 4d |
| M6 上线准备 | v1.0.0 | 安全加固、监控、备份、部署、压测 | 5d |
| **合计** | | | **约 37d** |

## M0 基础设施（v0.1.0）
- [ ] 公开 GitHub 仓库建立，`main` / `dev` 分支保护规则，默认分支设为 `dev`
- [ ] 后端骨架：`uv init`、FastAPI app factory、`/healthz`、`/readyz`、配置（pydantic-settings）、结构化日志
- [ ] ruff、pytest、pre-commit（含 gitleaks）、GitHub Actions CI
- [ ] 服务器：创建 PG 库 `aics` 与用户、Redis 库号 5/6、RabbitMQ vhost `aics`（见部署文档）
- [ ] 部署 Qdrant（`deploy/server/docker-compose.yml`）
- [ ] Alembic 初始化 + 首个迁移（users、roles）
- [ ] 前端骨架：Vite + Vue 3 + TS + Element Plus + 路由 + 登录页占位

**验收**：开发机 `uv run aics-api` 启动后 `/readyz` 返回 PG/Redis/RabbitMQ/Qdrant 全部 `ok`；CI 绿色。

## M1 知识库入库（v0.2.0）
- [ ] 表：apps、documents、chunks、jobs
- [ ] 存储接口 `Storage` + `LocalStorage`
- [ ] 解析器：PDF（PyMuPDF）、DOCX、MD、TXT、HTML、URL（trafilatura）
- [ ] 结构化切块器（标题路径、目标 500 token、重叠 80）
- [ ] 供应商抽象：`EmbeddingProvider`（DashScope 实现）
- [ ] Celery 任务：`ingest_document`（解析→切块→向量化→写 PG + Qdrant），状态流转与进度
- [ ] jieba 分词写入 `chunks.tsv`
- [ ] 内容哈希去重；软删除 + `cleanup_vectors` 任务
- [ ] 单元测试：解析器、切块器（固定样例文件）

**验收**：上传 3 种格式各 1 份，状态到 `done`，Qdrant 点数 = chunks 行数；删除后 5 分钟内向量被清理。

## M2 问答核心（v0.3.0）
- [ ] 表：conversations、messages
- [ ] `LLMProvider`（DeepSeek）、`RerankProvider`（DashScope qwen3-rerank）
- [ ] LangGraph：condense → retrieve(向量+关键词) → fuse(RRF) → rerank → judge → generate / refuse / handoff
- [ ] 提示词模板与引用标号 `[1][2]` 解析
- [ ] `POST /api/v1/chat` 阻塞 + SSE；多轮历史
- [ ] 记录 rewritten_query、检索快照、token、耗时
- [ ] 集成测试：可答 / 不可答 / 追问三类

**验收**：对样例知识库 20 个问题人工检查，可答题有引用，不可答题全部拒答或转人工；首 token 延迟 P50 < 2.5s。

## M3 开放接口（v0.4.0）
- [ ] api_keys 表、Key 生成（只显示一次）、哈希校验、过期、吊销
- [ ] Redis 令牌桶限流（按 Key 的 RPM）
- [ ] `/v1/chat/completions` OpenAI 兼容（含 stream）
- [ ] 知识库开放接口 + `Idempotency-Key`
- [ ] 反馈接口；统一错误码；OpenAPI 文档整理
- [ ] 隔离测试：A 应用的 Key 访问 B 应用资源一律 404

**验收**：用官方 `openai` Python SDK 改 `base_url` 即可对话；《接入指南》示例全部能跑。

## M4 管理后台（v0.5.0）
- [ ] JWT 登录/刷新、用户管理、角色与应用授权（user_app_roles）
- [ ] 应用列表/详情/配置编辑
- [ ] 知识库：上传（拖拽、多文件）、进度轮询、切块预览、重建、删除
- [ ] 调试对话：流式回答 + 右侧"检索面板"
- [ ] API Key 页面 + 复制即用示例
- [ ] 会话日志、反馈列表、审计日志、仪表盘

**验收**：viewer 不能修改任何东西（前后端都拦截）；所有页面操作在审计日志可查。

## M5 评测与质量（v0.6.0）
- [ ] eval_sets / eval_cases / eval_runs；CSV 导入
- [ ] 评测任务：检索命中率、引用命中率、拒答准确率、LLM 评判的答案正确性与忠实度
- [ ] 两次运行对比视图
- [ ] 点踩的回答一键加入评测集

**验收**：样例评测集达到非功能需求中的准确率指标，并有报告存档。

## M6 上线准备（v1.0.0）
- [ ] 安全检查清单逐项通过（见安全设计）
- [ ] `/metrics` + 告警规则；日志轮转
- [ ] 备份脚本 + 恢复演练一次
- [ ] 应用部署到服务器（Docker 镜像：api、worker、web）
- [ ] 压测：20 并发对话 10 分钟无错误
- [ ] 运维手册定稿；`dev` → `main`，tag `v1.0.0`，写 Release Notes

**验收**：内网同事按《接入指南》独立接入；按运维手册能完成重启、恢复、轮换密钥。

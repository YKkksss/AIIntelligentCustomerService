# 开发计划

> 每个阶段结束都必须**能运行、能演示**，并在 `dev` 上通过 CI。
> 分支模型：所有开发在 `dev` 或 `feature/*`（从 `dev` 拉出）上进行；每个里程碑达成后，`dev` 合并到 `main` 并打 tag（`vX.Y.Z`）。`main` 只保存已发布版本。详见 [Git 工作流](../06-development/04-Git工作流.md)。

> - ③ `tests/open_api.py` 登记开放接口（method / path / 请求体模板），`test_isolation_pg.py` 逐条断言 A 应用 Key 访问 B 应用一律 404；`tests/unit/test_open_api_coverage.py` 守卫任何未登记的新路由（CI 只跑非 integration，所以守卫必须在单测里）。当前 Starlette 1.8.0 把子路由保留为 `_IncludedRouter`，守卫改读 `app.openapi()["paths"]`。
> - 验收：单测 671 passed / 1 failed（`test_storage.py::test_symlink_escape_rejected`，Windows 建符号链接需特权，环境问题）、154 deselected，覆盖率 80.81%（门槛 80）；`ruff check` / `ruff format --check` / `lint-imports`（13 契约）/ `prompts check`（8 个）全绿；真实模型费用 0 元。集成用例 14 项（`test_keyusage_pg.py` 3、`test_apikeys_pg.py` 5、`test_isolation_pg.py` 6）与 beat 真实节拍**待服务器复验**（开发机无 PG / Redis / RabbitMQ / Qdrant，也无服务器凭据），见 [M3 测试报告](../06-development/10-M3测试报告.md)。
> - 与计划的两处偏差：解析与判定复用 `core/netguard.py` 的 `Allowlist` 而不是新增 `core/clientip.py`；新增 `AICS_TRUSTED_PROXIES` 的启动校验（非法 CIDR 启动即失败，避免静默地不信任任何代理）。

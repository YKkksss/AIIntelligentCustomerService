# 开发计划

> 每个阶段结束都必须**能运行、能演示**，并在 `dev` 上通过 CI。
> 分支模型：所有开发在 `dev` 或 `feature/*`（从 `dev` 拉出）上进行；每个里程碑达成后，`dev` 合并到 `main` 并打 tag（`vX.Y.Z`）。`main` 只保存已发布版本。详见 [Git 工作流](../06-development/04-Git工作流.md)。

## 里程碑总览
| 里程碑 | 版本 tag | 内容 | 依赖 |
|---|---|---|---|
| M0 基础设施 | v0.1.0 | 仓库、工程骨架、core 基础工具、服务器服务就绪 | — |
| M1 知识库入库 | v0.2.0 | 上传→解析→切块→向量化→版本化入库 | M0 |
| M2 问答核心 | v0.3.0 | LangGraph RAG + memory + chat 编排 + 会话生命周期 + 对话接口（阻塞/SSE） | M1 |
| M3 开放接口 | v0.4.0 | API Key、限流、OpenAI 兼容、知识库接口、转人工与 Webhook、会话事件流 | M2 |
| M4 管理后台 | v0.5.0 | 登录、应用（含会话/转人工/Webhook 配置）、知识库、调试对话、Key、日志、统计、系统设置 | M3（后台只调公开接口） |
| M5 评测与质量 | v0.6.0 | 评测集/运行、反馈、调参对比 | M2（评测复用 chat.service）、M4（评测页面） |
| M6 上线准备 | v1.0.0 | 安全加固、监控、备份、部署、压测 | M0–M5 |

---

## M0 基础设施（v0.1.0）
- [ ] 公开 GitHub 仓库建立，`main` / `dev` 分支保护规则，默认分支设为 `dev`
- [ ] 后端骨架：`uv init`、FastAPI app factory、`/healthz`、`/readyz`、配置（pydantic-settings，含 `AICS_MODELS` 注册表校验）、结构化日志
- [ ] 基础工具：`core.tokens`（唯一 token 计数）、`core.textsearch`（按应用分词器缓存、`build_tsquery`）、`core.prompts`（front-matter 加载 + CI 版本检查）、`db.AppScopedRepository`
- [ ] import-linter 依赖规则（见模块划分 §3）接入 CI
- [ ] ruff、pytest、pre-commit（含 gitleaks）、GitHub Actions CI
- [ ] 服务器：创建 PG 库 `aics` 与用户、Redis 库号 5/6、RabbitMQ vhost `aics`（见部署文档）
- [ ] 部署 Qdrant（`deploy/server/docker-compose.yml`）
- [ ] Alembic 初始化 + 首个迁移（users、roles）
- [ ] 前端骨架：Vite + Vue 3 + TS + Element Plus + 路由 + 登录页占位

**验收**：开发机 `uv run aics-api` 启动后 `/readyz` 返回 PG/Redis/RabbitMQ/Qdrant 全部 `ok`；CI 绿色。

## M1 知识库入库（v0.2.0）
- [ ] 表：apps（含 `status` deleting、`chunk_config_version`）、documents（`version`、`index_version`、`pending_index_version`、`status` deleting）、chunks（`index_version`、`review_status`）、jobs（完整 type 清单、`cancelled`）
- [ ] 存储接口 `Storage` + `LocalStorage`
- [ ] 解析器：PDF（PyMuPDF）、DOCX、MD、TXT、HTML、URL（trafilatura）
- [ ] 结构化切块器（标题路径、目标 500 token、重叠 80，计数用 `core.tokens`）
- [ ] `rag/config.py`：`AppRagConfig` 等配置 schema（apps 模块持久化与校验）
- [ ] 供应商抽象：`EmbeddingProvider`（DashScope 实现）
- [ ] Celery 任务（队列 `ingest` / `maintenance`，只调用 service）：`ingest_document` 版本化构建（新构建号写入 → 事务切换 → `cleanup_document` 清旧版本），状态流转与进度，删除状态检查与中止
- [ ] 按应用 jieba 分词写入 `chunks.search_text`/`tsv`；`retokenize_app`
- [ ] 入库注入检测 → `review_status=flagged`
- [ ] 内容哈希去重；删除（`deleting` → `cleanup_document`）；替换文档（FR-KB-08，`replace` job）
- [ ] 单元测试：解析器、切块器（固定样例文件）

**验收**：上传 3 种格式各 1 份，状态到 `done`，Qdrant 点数 = 生效版本 chunks 行数；重建期间旧版本可检索；删除后 5 分钟内向量被清理。

## M2 问答核心（v0.3.0）
- [ ] 表：conversations（`status`、`closed_at`、`last_activity_at`、`idle_notice_sent_at`、`handoff_status` 等、`summary*`）、`system_settings`；messages（`role` 四值、`kind`、`agent_id`、`token_count`、`search_text/tsv`、`intent*`、`prompt_version`、`citations` 统一结构）
- [ ] `LLMProvider`（DeepSeek）、`RerankProvider`（DashScope qwen3.7-text-rerank）
- [ ] LangGraph：guard → intent_match（占位）→ load_context → condense_classify → route → retrieve(向量+关键词) → fuse(RRF) → rerank → judge → generate / refuse / handoff → postprocess；入口 `run_rag(RagInput, ports)` 带 `RunMode`，只返回 `RagResult`
- [ ] `rag.ports`（`MemoryPort`、`ChunkSearch`）；`knowledge.chunk_search` 实现关键词检索（OR tsquery）
- [ ] 提示词文件（front-matter 版本）与引用标号 `[1][2]` 解析；`prompt_version` 落库
- [ ] 会话生命周期：`session_config` + 平台默认、beat `idle_sweep`（每 30 秒提醒/关闭）、关闭后自动新建会话（`previous_conversation_id`）；见[会话生命周期与转人工](../02-architecture/09-会话生命周期与转人工.md)
- [ ] `chat.service.handle_turn`：会话校验、生成前落 user 消息、生成后落 assistant 消息（`interrupted` / `error`）、`refusal_streak` / `handoff_status`（→ pending）更新、按转人工状态分派（`reply_by`）、压缩触发
- [ ] `POST /api/v1/apps/{app_id}/chat` 阻塞 + SSE（citations 仅在判定可答后发送）
- [ ] 记录 rewritten_query、检索快照、token、耗时
- [ ] `aics.memory` 基础版：`ConversationStore`、`load_context`（token 预算 + 保底轮数）；`compact_conversation` 滚动摘要任务（队列 `context`、Redis 锁、版本乐观锁、重试，eval 同步路径）；见[对话上下文管理](../02-architecture/07-对话上下文管理.md)
- [ ] 意图识别：`aics.rag.intent` 纯函数包；guard 规则层（敏感词、转人工词、寒暄完全匹配模板）；`condense_classify` 合并分类与兜底链；无历史时分类与检索并行；chitchat / human / out_of_scope 分支，action → 转人工，简单 clarify；响应与 trace 增加 `intent`；见[意图识别](../02-architecture/08-意图识别.md)
- [ ] 集成测试：可答 / 不可答 / 追问三类 + 30 轮长对话触发压缩 + 寒暄两次不转人工、超范围不检索、意图注入回落 kb_qa + 空闲提醒与关闭后自动新建 + 转人工 continue/wait 分派

**验收**：对样例知识库 20 个问题人工检查，可答题有引用，不可答题全部拒答或转人工；首 token 延迟 P50 < 2.5s。

## M3 开放接口（v0.4.0）
- [ ] api_keys 表、Key 生成（只显示一次）、哈希校验、过期、吊销
- [ ] Redis 令牌桶限流（按 Key 的 RPM）
- [ ] `/v1/chat/completions` OpenAI 兼容（含 stream），复用 `chat.service`；无状态按预算裁剪 + 临时摘要；`X-AICS-Conversation-Id` 关联会话
- [ ] 知识库开放接口（含替换、改标题）+ `Idempotency-Key`
- [ ] 转人工：`aics.modules.handoff` 状态机与坐席入站接口（scope `handoff:write`）
- [ ] 转人工超时与留言：排队超时、服务时间（周计划 + 时区）与非服务时间留言、接入后无消息超时（均在 `idle_sweep` 内）；待回访标记与后台列表/清除
- [ ] `aics.modules.webhooks`：固定格式事件、HMAC 签名、`webhook_deliveries`、退避重试（队列 `context`）、SSRF 校验；`AICS_DATA_ENCRYPTION_KEY`
- [ ] 会话事件流 SSE（Redis pub/sub、`Last-Event-ID` 补发）
- [ ] 反馈接口；统一错误码；OpenAPI 文档整理
- [ ] 隔离测试：A 应用的 Key 访问 B 应用资源一律 404

**验收**：用官方 `openai` Python SDK 改 `base_url` 即可对话；《接入指南》示例全部能跑；用示例接收端完成一次 requested → accepted → 人工回复 → released 全流程，签名校验通过。

## M4 管理后台（v0.5.0）
- [ ] JWT 登录/刷新、用户管理、角色与应用授权（user_app_roles）、RBAC 权限清单与 `require_perm` / `v-perm`
- [ ] 应用列表/详情/配置编辑（模型下拉来自 `/models`；会话、转人工、Webhook 分组）；系统设置页（平台默认会话设置）；应用删除（`deleting` + `cleanup_app`）
- [ ] 知识库：上传（拖拽、多文件）、进度轮询、切块预览、重建、替换、删除、待复核切块
- [ ] 调试对话：流式回答 + 右侧"检索面板"（含「上下文」「意图」Tab）；会话日志摘要版本与意图筛选；配置页意图分组
- [ ] API Key 页面 + 复制即用示例
- [ ] 会话日志（人工/系统消息、转人工时间线、后台释放）、反馈列表、审计日志
- [ ] `aics.modules.stats` + `app_daily_stats` 表 + beat `aggregate_daily_stats`；仪表盘读统计表

**验收**：viewer 不能修改任何东西（前后端都拦截）；所有页面操作在审计日志可查。

## M5 评测与质量（v0.6.0）
- [ ] eval_sets / eval_cases / eval_runs（`prompt_versions`）；CSV 导入（文档 ID / 唯一标题校验）
- [ ] 评测运行复用 `chat.service`（`RunMode.eval`、同步压缩、`channel=eval`）
- [ ] 评测任务：检索命中率、引用命中率、拒答准确率、LLM 评判的答案正确性与忠实度
- [ ] 两次运行对比视图
- [ ] 点踩的回答一键加入评测集（`feedback.eval_case_id`、`source_feedback_id`）
- [ ] 长对话评测用例（20 轮以上）与细节保持率指标
- [ ] 依评测结果决定是否上线：`conversation_facts` 关键事实槽（压缩抽取 + 逐轮槽位写入）、消息向量化（`AICS_MESSAGE_EMBED_ENABLED`）与会话内回查
- [ ] 意图评测：`expected_intent`、30–50 条意图用例；意图准确率、寒暄误拒率、误转人工率、知识问答漏答率；校准 `min_confidence` / `clarify_threshold`；决定是否上向量快速通道（`intent_examples`）

**验收**：样例评测集达到非功能需求中的准确率指标，并有报告存档。

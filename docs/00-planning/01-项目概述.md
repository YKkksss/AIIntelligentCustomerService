# 项目概述

## 1. 背景
公司内部和合作方有大量"按资料回答问题"的客服需求：售前咨询、售后政策、HR 制度、IT 帮助台……它们的流程几乎一样，区别只在资料。AICS 把这件事做成**一个平台**：资料换了，客服就换了。

## 2. 一句话定义
> 上传知识库 → 配置一个应用 → 拿到 API Key → 任何系统通过接口接入一个"只按资料回答、会标出处、答不了会转人工"的 AI 客服。

## 3. 目标
| 编号 | 目标 | 衡量方式 |
|---|---|---|
| G1 | 对外 API 稳定可接入 | 第三方 30 分钟内按《接入指南》跑通；OpenAPI 文档完整 |
| G2 | 回答可信 | 评测集上：答案正确率 ≥ 80%，引用命中率 ≥ 85%，不可答问题拒答率 ≥ 90%（见非功能需求） |
| G3 | 多应用隔离 | 任何接口都无法读到其他应用的数据（有自动化测试覆盖） |
| G4 | 可运营 | 后台可看日志、反馈、评测趋势；改配置后能用评测对比效果 |
| G5 | 可上线 | 一键部署、备份、监控、运维手册齐全 |

## 4. 用户角色
| 角色 | 说明 |
|---|---|
| 接入方（开发者） | 用 API Key 调用对话与知识库接口 |
| 终端用户 | 在接入方的系统里和客服聊天，不直接接触 AICS |
| super_admin | 平台管理员：管理所有应用、用户、全局配置 |
| app_admin | 应用管理员：管理被授权的应用（知识库、配置、Key、评测） |
| viewer | 只读：查看日志、反馈、评测结果，可在调试对话中测试 |

## 5. 核心原则
1. **只按资料回答**：检索不到足够相关的内容，就拒答或转人工，不靠模型"自由发挥"。
2. **处处有出处**：每个回答都带引用（文档名、标题路径、片段）。
3. **可度量**：每个改动都能用评测集跑出数字对比。
4. **可替换**：LLM、向量化、重排序、文件存储都通过接口抽象，改配置即可换。
5. **接口优先**：后台页面也只调用公开的 HTTP 接口，后台能用 = 接口可用。

## 0.1 维护约定（重要）

1. **发现即登记**，不要只写在提交信息里：新增行用 `ISSUE-nn`（递增，不复用编号）。
2. 每行必须写清 **证据**（文件:行 / 命令 / 文档位置）、**影响**、**状态与何时处理**。「以后再说」「有空再看」不算时机，要么写明确里程碑（如 M5.4），要么写明确条件（如「服务器有凭据后」）。
3. **每个子步骤收尾时扫一遍本表**：有没有本步引入的、本步解决的、本步已经到期的。解决的移到 [§4 已解决](#4-已解决归档)，写日期 + 提交号，**不删行**。
4. 状态取值：`待处理`（没定时间）/ `计划内`（已写明里程碑）/ `待复验`（等服务器或等前置模块）/ `已接受`（决定不修，必须写理由）/ `已解决`（在 §4）。
5. 优先级：`P0` 阻塞交付、`P1` 影响正确性或对外承诺、`P2` 打磨与整洁。
6. 变更本文档时，同一提交里同步 [文档索引](../README.md) 中的说明（如果改的是本文档的用途）。
